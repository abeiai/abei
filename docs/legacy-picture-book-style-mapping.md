## 来源识别与导入

`tools/legacy_sync/book_styles.py` 优先读取 `result[0].extra.draw.style`，支持旧 ID、旧名称及含 `id` / `title` 的选中项。不从 `config.draw_style` 的可选目录、角色外貌描述或角色历史图片中猜测当前绘本的风格。

没有选中项时，使用作品的 `extra.one_take_id` 关联认证快照中的任务；任务用户必须等于作品用户，任务封面必须等于作品封面，再通过稳定原生日志 ID 读取已导入的绘画记录。日志必须同时匹配来源系统、来源表、源主键和源用户 ID，才能采用 `parameters.source.style_id`。无法关联时使用平面插画。明确保存的绘本风格优先于历史记录。

`native_mapping.book_row` 在新导入时直接写入新版稳定风格 ID；原生核心导入和增量对账使用相同历史解析。增量包仍沿用既有采集范围：旧任务若不在当前包、或对应绘画日志缺失，视为无法恢复并归入平面插画，不扩大旧源采集或 R2 上传范围。目标风格目录需启用表中 ID；管理员改名不会影响稳定 ID 的选中状态。

## 既有绘本补填

`tools/legacy_sync/book_style_repair.py` 仅补填匹配旧源身份且 `style=''` 的既有绘本。归属及创建时间必须一致，目标版本、更新时间和整个目标行除 `style` 外的 SHA-256 必须与备份一致。已选择的中文风格、稳定 ID、自定义风格都保留；正文已编辑但仍未选风格的旧绘本可以补填，正文及版本不改动。

整个计划在一个事务内检查并应用，复用迁移锁；目标身份、页面、正文、素材或风格出现并发变化，整批回滚。重复应用同一计划应为零修改。应用前加密保存风格前像及计划，应用后逐本验证所有非风格字段的 SHA-256；修复风格不推进增量游标，不调整订单、余额、权限、作品公开状态或素材地址。

运行信息保存在本地 Git 忽略目录 `.superpowers/legacy-sync/style-repair-run.json`，其所指目录的 `reports/before-production.enc` 保存线上前像，`reports/plans-production.enc` 保存计划，`reports/verification.enc` 保存对账。独立密钥留在既有包外密钥目录。实际应用须验证 Compose 项目为 `abei-prod`、数据库为 `abei`、端口为 `3604`，不能使用全库覆盖。
