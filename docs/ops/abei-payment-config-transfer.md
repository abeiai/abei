# abei 支付配置同步

本任务只修改 `tools/payment_config/` 的配置迁移工具和本说明；不改支付处理、微信登录、数据库 schema 或 seed。源为用户指定的 xueleai 生产支付配置，目标为 abei 本地与生产 `system_configs`，不复用源数据库连接、应用加密密钥或数据卷。

## 同步规则

- 源库使用显式只读事务，检查数据库 `xueleai`、内部端口 3327。只读取支付模块定义的 23 个配置键；源应用内解密后通过 SSH 和独立 AES-GCM 加密包传递。
- 目标检查数据库 `abei`、内部端口 3604；使用各自运行环境的 `SECRET_ENCRYPTION_KEY` 重新加密，所有配置保持 `isPublic=false`。
- 线上回调统一指向 `https://new.abeiai.com/api/payment/{alipay,wechat}/notify`；支付宝返回页为 `/dashboard/billing`，JSAPI 回调为 `/api/payment/wechat/jsapi/callback`。源空字段保持为空。
- 本地回调使用 `http://localhost:3600`，两个支付总开关保持关闭，避免真实付款回调指向线上而本地订单无法入账。
- 先保存目标加密备份，再检查配置未被并发修改、没有 CREATED/PAYING 订单，使用事务写入。事务内任一失败全部回滚。两个目标按顺序执行并分别报告，不构成跨服务器事务。明文相同的密钥保留原密文，重复执行零修改。
- 原旧版 AQiPay 配置不导入。本次不调用支付下单、查询、退款或通知接口。

## 验收

迁移测试命令：`node --test tools/payment_config/transfer.test.mjs`。真实数据库测试需通过私有运行器向 `ABEI_LEGACY_TEST_DATABASE_URL` 注入独立测试库连接（仅允许 `127.0.0.1:3606/abei_wechat_test`）；普通运行未提供该连接时会跳过数据库测试，不可作为写库验收。

验收页面：`/admin/payment-config`、`/dashboard/billing`。线上检查原生支付配置服务的读取、可用场景、通知地址及加密解密；公共配置接口不可包含支付配置。比较同步前后其他配置、订单、钱包、流水、支付通知与冻结记录的摘要，并验证重复执行零修改。

正常页面读取系统配置时，现有 `ensureDefaults()` 会刷新其他配置的 `updatedAt`；保留数据复验忽略其他配置的该时间字段，仍逐项比较配置值、标签、公开属性及其余字段。支付配置自身的 CAS 与全部账务记录仍精确比较。

## 2026-10-10 源配置核对

xueleai 线上只有微信 Native 扫码支付已配置并启用。支付宝凭据为空，H5 和 JSAPI 未启用；同步保持这些状态。本次不补造支付宝凭据，也不使用旧版聚合支付密钥代替官方支付密钥。

执行结果：本地更新 8 项，线上更新 9 项；两端应用原生配置服务均确认微信配置可读取，线上可用场景仅 `WECHAT_NATIVE`，本地支付开关关闭。两端凭据一致性复验通过，重复执行均零修改；其他业务配置及全部账务摘要与同步前一致，源配置保持不变。6 项迁移测试（含独立 PostgreSQL 并发、回滚和重放）与 8 项现有支付测试通过；两端健康和公共配置接口复验通过，公共响应不包含支付配置。

没有应用代码、依赖、schema 或 seed 变更，因此未执行全站构建或部署。未发起真实付款，支付与到账闭环尚未实测。

支付宝后续需提供正式应用 AppID、应用 RSA 私钥及支付宝公钥。若以后启用微信 H5 / JSAPI，还需核对 abei 域名的商户平台及公众平台配置，JSAPI 同时需要对应公众号 AppSecret。实际付款与到账闭环需要另行执行一笔受控支付验证。

私有凭据、加密包、备份、服务器密钥和真实数据库地址均不得提交 Git 或写入公开日志。备份保存在被忽略的私有任务目录，解密密钥另存用户本地密钥目录。
