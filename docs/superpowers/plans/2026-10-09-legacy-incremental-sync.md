# 旧版增量导入实施方案

> 执行：本会话按 `superpowers:executing-plans` 实现，严格模式；独立代理只审查，不接触真实配置、数据或网络。

**目标：** 从最后一次已应用数据库快照导入新增用户、生成记录、素材与兼容作品，形成可重复执行的增量流程。

**架构：** 每批在旧 MySQL 的同一个 READ ONLY / REPEATABLE READ 快照中采集。按每表主键高水位获取新增记录，同时用上次快照起点前 10 分钟的重叠窗口获取有 `req_time`、`res_time`、`create_time`、`update_time` 的变更；用户、普通会话及模型版本作为依赖完整读取。独立加密包保留 176 表目录，但明确标为增量，不冒充全量备份。离线导入新版本地库并复制本批可信用户素材到现有公开 `abeiai` R2，最后对账后推进本地游标。

**技术：** 现有 Python 3.12、AES-GCM 包、MySQL 只读采集、受限 PostgreSQL、R2 条件创建。

**范围：** 允许改 `tools/legacy_sync`、迁移文档及忽略的本地运行脚本；不得改旧源码、真实环境配置、网页、数据库 schema 或 seed。无 migration / seed 更新。

## 固定规则

- 旧库与旧对象源只 SELECT / GET / HEAD；不调用旧业务 API，不修改源访问策略。
- 采集、上传、目标导入分开进程及凭据；目标只允许 abei 本地 3604 或隔离测试 3606。
- 来源指纹、源命名空间、父批次和完整表高水位必须绑定，空表不能丢失原高水位。
- 用户仅新增，保留已升级密码与新版身份；不自动合并身份冲突，不激活旧余额、订单履约或管理员。
- 旧生成日志可按可信源身份和快照时间刷新完成状态；旧批次重放不得覆盖新批次。
- 会话追加位置须承接原位置，重复执行不产生重复关联。
- 素材只扫描增量记录及新增用户头像，完整依赖读取不触发历史素材重传；直接用户和普通会话归属之外的素材继续留档。
- 新兼容绘本可插入，已存在绘本及交互编辑保持不覆盖；其他作品保留加密档案和本批素材。
- 缺失素材留存加密明细，最多一次自动重试；数据库应用游标与素材缺失清单分开记录。

## 审查重点

1. 错误来源、过期/分叉父批次、空表及边界时间不能漏采或重置游标。
2. 异步生成完成以及新消息落在旧会话中的状态和顺序正确。
3. 依赖读取不能扩大素材范围，也不能把未知用户归属映射到测试用户。
4. 重放不得回退日志状态、密码、身份、作品版本或原有财务/管理数据。
5. 断连不能产生可应用包；只在包、原生数据及素材对账通过后登记新的应用游标。

## 明确的后续开发要求

无通用修改时间的旧表只能保证新增主键覆盖；硬删除、超出重叠窗口的长事务以及未更新时间的原地修改需要 CDC 或定期全量核对。旧作品正文更新、间接归属、订单状态及余额/权益映射仍需独立业务开发。旧版生成代码的正常完成路径会写 `res_time`，增量同时读取请求和响应时间，不把文件访问时间混同为生成时间。
