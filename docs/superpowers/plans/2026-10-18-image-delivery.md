# 图片交付优化 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; one independent review at the end.

**Goal:** 列表获取小图、阅读获取清晰大图，新增与历史图片均能优化，保留原图与鉴权。

**Architecture:** 公开静态/受信任远程图片使用现有 Next.js/Sharp 缓存；原有媒体文件与绘本接口支持固定宽度参数，鉴权后读取私有衍生缓存。上传保留原文件，预热 320/640 两个规格；历史资源按需生成。统一前端组件提供 srcset/sizes、优先级与失败回退。

**Tech Stack:** Next.js 16、NestJS、Sharp 0.34.5、node:test。

**Spec:** 本聊天已获用户批准的图片优化方案及 AGENTS.md。

## Global Constraints
- 仅修改图片前后端、相关测试、Docker 缓存配置与文档；不修改数据库 schema/seed、支付、登录、AI 生成流程或用户未提交文件。
- 所有新端口使用 3600–3680；测试数据库必须独立，不复用 xueleai。
- 不部署、不修改云资源；后续 CDN 通过公开域名配置接入。
- 原始请求无 w 参数时行为保持；私有图每次访问先鉴权，缓存不作为授权依据。
- 固定宽度 64/128/160/320/640/960/1280/1920；小图 WebP q82，阅读图 q90；不放大、不裁剪；动图/不支持格式保留原文件。

## Review Focus
- 私有接口命中衍生缓存仍需权限；不开放任意远程代理。
- 方向、透明度、动画与含文字阅读图；原图不被覆盖。
- 版本与缓存键不混用；缓存目录不可通过静态入口访问，磁盘/并发有界。
- 首屏优先级与相邻页面预加载；失败时重试不会无限循环。
- 本地与生产 Docker 可写缓存目录；新增/历史图片及原地址兼容。
