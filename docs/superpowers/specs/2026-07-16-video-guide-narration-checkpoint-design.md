# 视频导学文案分批与断点续跑设计

## 目标

降低视频导学文案生成耗时，并让 API Core 重启或单批失败后可以从已完成部分继续生成。

## 生成结构

一次文案任务按以下顺序执行：

1. 单独生成课程导入。
2. 将有效字幕固定按每批 4 句生成逐句讲解。
3. 单独生成课程总结。

导入和总结读取完整字幕上下文，但只返回各自节点。逐句批次只返回目标句子的 `sentences`，不再要求每一批重复输出导入和总结。

## AI 调用

`video-guide-narration-timeline` 场景新增 `generationMode` 变量，值为 `INTRO`、`SENTENCES` 或 `SUMMARY`。所有本场景的非流式调用显式设置 `reasoningEnabled: false`，AI Service 将模型是否支持思考和关闭状态传递给 AI Gateway。

批次大小固定为 4，不再接受环境变量覆盖。单批仍保留现有有限重试和递归拆分能力，作为模型输出异常时的兜底。

## 持久化与恢复

课件 `content.narrationGenerationCheckpoint` 保存：

- 版本号和字幕内容指纹
- 固定批次大小及批次数量
- 已成功的导入、逐句和总结节点
- 首次成功调用的模型、供应商和 AI 任务元数据
- 最近更新时间

字幕指纹包含视频标题及所有有效字幕的句子 ID、文本和时间轴。恢复时只有指纹完全一致的检查点可以复用；字幕或标题变化后自动创建新检查点。

每个部分成功后立即读取当前课件、合并检查点和进度，再通过 `narrationGenerationId` 租约做 CAS 更新。旧执行器失去租约后不能覆盖新任务。自动恢复和同课件失败后重新提交时保留有效检查点，最终文案成功后删除检查点。

## 错误处理

检查点写入失败或租约失效时立即终止当前执行器。最终组装前仍验证导入、全部有效 sentenceId 和总结是否完整，避免把部分文案标记为成功。

## 验证

- 单元测试覆盖固定四句分批、三种生成模式解析、检查点合并与指纹失效。
- 服务测试覆盖检查点写入的租约 CAS 条件。
- AI Service 测试或类型级验证确认非流式调用传递思考开关。
- 运行 API Core 定向测试和 TypeScript 类型检查。
