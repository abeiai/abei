# 用户课程创建、审核与公开发布设计

**日期：** 2026-07-17

**状态：** 已确认，待实施计划

**范围：** 用户创建课程、统一后台审核、资源中心、公开课程页，以及视频导学、英文带读、学习闪卡的课程化发布

## 1. 目标

登录用户可以把本人制作的视频导学、英文带读和学习闪卡组合成课程，填写课程名称、4:3 封面、简介和标签，修改课程内课件名称与顺序，再提交管理员审核。

审核通过的课程进入公开资源中心 `/center`，并使用永久稳定的 `/c/{courseId}` 详情地址。课程与其中课件允许匿名访问，点击课件后进入对应工具已有的原生学习页面。

本功能必须同时满足：

- 课程 URL 稳定，不因复审而消失。
- 已上线课程复审时继续展示上一个审核通过版本。
- 课程级变更复审期间，整份课程目录不可点击。
- 单个原始课件内容变更时，只锁定该课件，不影响课程和其他课件。
- 课程变更和课件变更由管理员在同一个界面处理。
- 系统明确展示修改前后差异。

## 2. 非目标

本次不实现付费课程、订阅、钱包扣点、教师认证、多语言、复杂角色权限、课程分类管理、课程评论、收藏、学习进度、证书、协同编辑、版本回滚或可视化课程搭建器。

不修改支付、钱包、组织、AI 网关及现有管理员角色体系。

## 3. 方案选择

采用“版本化课程 + 独立课件审核”方案。

课程保留已审核版本和编辑版本；原始课件保留独立的公开审核状态。课程信息或目录变化产生课程审核请求，已公开课件内容变化产生课件审核请求。两类请求进入同一管理员审核队列。

不采用单表 JSON 双快照方案，因为它会削弱课件引用完整性、排序查询和后续维护能力。不采用发布时复制全部课件方案，因为它会重复内容，并破坏现有学习页复用。

## 4. 数据模型

### 4.1 Course

课程稳定身份，包含：

- `id`：服务端使用安全随机数生成的 24 位小写十六进制字符串。
- `userId`：课程作者。
- `approvedRevisionId`：最近一次审核通过版本；首次通过前为空。
- `workingRevisionId`：当前草稿、待审或被拒绝版本。
- `reviewState`：`DRAFT`、`PENDING_REVIEW`、`PUBLISHED`、`REJECTED`。
- `publishedAt`：首次审核通过时间。
- `createdAt`、`updatedAt`。

课程 ID 生成后永久不变，公开地址固定为 `/c/{id}`。

### 4.2 CourseRevision

课程内容版本，包含：

- 课程名称。
- 封面媒体引用。
- 课程简介。
- 标签数组。
- 版本状态：`DRAFT`、`PENDING`、`APPROVED`、`REJECTED`。
- 提交、审核、拒绝原因和时间信息。
- 有序的 `CourseRevisionItem` 列表。

公开页面始终读取 `approvedRevisionId` 指向的版本。用户编辑已上线课程时，从已审核版本复制出新的工作版本；审核通过后原子切换公开版本，审核拒绝后继续公开旧版本。

### 4.3 CourseRevisionItem

课程版本中的课件条目，包含：

- `revisionId`。
- 课件类型：`VIDEO_GUIDE`、`ENGLISH_GUIDED_STUDY`、`LEARNING_FLASHCARD`。
- 三个可空来源外键：视频导学、英文带读、学习闪卡；数据库约束保证只能有一个非空。
- 课程内显示名称。
- `sortOrder`。
- 对应的 `CourseMaterialPublication`。

课程内改名不修改原始课件名称。

### 4.4 CourseMaterialPublication

原始课件的公开审核身份。相同课件被多个课程引用时共用一条记录，包含：

- 课件类型与来源外键。
- `status`：`PENDING`、`APPROVED`、`REJECTED`。
- 上次已审核内容指纹。
- 当前内容指纹。
- 最近一次结构化内容快照。
- 创建和更新时间。

首次课程审核通过时，同时批准课程中尚未公开审核的课件。以后原始课件内容发生变化，只更新该课件的公开审核状态，不改变课程版本。

### 4.5 CourseReviewRequest

统一审核请求，包含：

- 审核范围：`COURSE_REVISION` 或 `MATERIAL_CHANGE`。
- 课程版本或课件公开记录引用。
- `beforeSnapshot`、`afterSnapshot`。
- 结构化 `diff`。
- 状态：`PENDING`、`APPROVED`、`REJECTED`。
- 提交人、审核管理员、审核意见和各时间字段。

同一课件在待审期间连续修改时，更新现有待审请求为最新差异，不创建重复请求。

### 4.6 MediaAsset

在现有媒体资产上增加用户上传归属，用于课程封面。管理员媒体上传关系与现有行为保持不变。

## 5. 状态与公开规则

### 5.1 首次发布

1. 用户创建草稿。
2. 用户提交后，课程和未审核课件进入待审状态。
3. 首次审核通过前，课程不出现在 `/center`，匿名访问 `/c/{id}` 不返回未审核内容。
4. 审核通过后设置 `approvedRevisionId`、`publishedAt` 并进入资源中心。
5. 审核拒绝后向作者显示中文原因，作者可继续编辑并重新提交。

### 5.2 已上线课程复审

1. 作者修改课程名称、封面、简介、标签、课件集合、课程内名称或排序。
2. 系统创建新的工作版本和课程审核请求。
3. `/center` 与 `/c/{id}` 继续显示上次审核通过版本，并显示“审核中”。
4. 复审期间整份课程目录不可点击。
5. 审核通过后原子切换到新版本。
6. 审核拒绝后恢复正常发布状态，继续使用旧版本；被拒绝工作版本保留给作者修改。

### 5.3 已发布课件内容变化

1. 只有课件已被至少一个公开课程引用时，内容修改才触发公开课件审核。
2. 系统在内容写入前后生成标准化快照、内容指纹和差异。
3. 所有引用该课件的课程仍保持公开。
4. 课程目录中只有该课件显示“课件审核中”并不可点击。
5. 其他已审核课件继续正常学习。
6. 审核通过后更新已审核内容指纹并恢复点击。
7. 审核拒绝后该课件继续不可点击，作者看到拒绝原因；再次修改后重新进入审核。

置顶、学习进度和闪卡复习记录等个人行为不属于公开内容变化，不触发审核。

## 6. 用户体验

### 6.1 我的课程

新增 `/dashboard/courses`：

- 展示本人课程及草稿、审核中、已发布、审核未通过状态。
- 显示封面、名称、更新时间、课件数量和拒绝原因摘要。
- 提供创建、编辑、预览和查看公开页入口。

### 6.2 创建与编辑

新增 `/dashboard/courses/new` 和 `/dashboard/courses/{id}`：

- 输入课程名称、课程简介和标签。
- 上传 JPEG、PNG、WebP 封面并裁切为 4:3。
- 从本人课件中选择已完成的视频导学、已生成的英文带读和状态为可学习的学习闪卡。
- 在课程目录中改名、移除并使用可访问的上下移动控件排序。
- 提供“保存草稿”和“提交审核”。
- 至少包含一个课件才可提交。
- 待审版本不可继续修改；被拒绝后可继续编辑。

### 6.3 资源中心

新增 `/center`：

- 只列出至少审核通过一次的课程。
- 卡片展示 4:3 封面、课程名称、简介摘要、标签、课件数量和审核状态。
- 首版不增加分类、复杂筛选、收藏或推荐算法。

默认前台导航与 seed 中加入“资源中心”。不创建虚假课程或审核数据。

### 6.4 公开课程页

新增 `/c/{courseId}`：

- 展示 4:3 封面、课程名称、作者昵称、简介、标签和有序课件目录。
- 不公开作者邮箱、内部存储键、审核意见或未审核版本。
- 正常课件跳转到现有原生学习页：
  - 视频导学：`/media-tutor/{shareToken}`。
  - 英文带读：`/text2lesson/{id}`。
  - 学习闪卡：`/flashcard/{id}`。
- 为至少随一个课程审核通过过的学习闪卡增加匿名读取能力；课件后续待审状态只控制课程页入口，不使原学习地址失效。
- 课程级审核中时禁用全部课件；课件级审核中时只禁用对应课件。

## 7. 管理员审核

新增 `/admin/course-reviews`，用一个页面处理两类请求。

列表展示：

- 审核类型。
- 提交用户。
- 课程或课件名称。
- 提交时间。
- 受影响课程数量。
- 当前状态。

详情展示结构化变更：

- 课程名称修改前后。
- 封面修改前后预览。
- 简介文本差异。
- 标签新增和删除。
- 课件新增、删除、改名和排序变化。
- 视频导学的字幕、讲解文案、练习和音频变化。
- 英文带读的原文、讲解、逐句内容和音频变化。
- 学习闪卡新增、删除、修改的卡片，以及正面、背面、标签等字段变化。
- 课件变更影响的所有公开课程。

审核通过必须在事务中完成。审核拒绝必须填写简体中文原因。每次管理员审核写入现有管理员操作日志。

## 8. API 边界

### 8.1 用户 API

- 创建、读取、更新本人课程草稿。
- 查询本人可选的三类课件。
- 上传课程封面。
- 保存课程课件名称和顺序。
- 提交课程审核。
- 查询审核状态和拒绝原因。

### 8.2 管理员 API

- 查询统一审核队列。
- 查询审核详情与结构化差异。
- 审核通过或拒绝。

### 8.3 公开 API

- 查询已公开课程列表。
- 按课程 ID 查询公开课程详情。
- 匿名读取至少随一个课程审核通过过的学习闪卡；后续课件复审不使原学习地址失效。

全部 NestJS API 继续使用统一响应结构：

```ts
{
  code: number;
  message: string;
  data: unknown;
}
```

## 9. 校验、安全与并发

- 所有用户写接口必须从登录态获取用户身份。
- 后端必须重新验证课程和每个课件的所有权。
- 只能选择状态完整、可以学习的课件。
- 管理员接口必须验证管理员身份。
- 公开 API 只返回已审核版本所需字段。
- 课程 ID 使用密码学安全随机数，不使用顺序 ID。
- 封面只允许 JPEG、PNG、WebP，最大 10MB；服务端验证真实文件类型、像素尺寸和 4:3 比例，再复用本地或 S3 存储。
- 标签去重并限制数量与单项长度。
- 课程名称、简介和课程内课件名称执行长度校验。
- 审核通过使用数据库事务和条件更新，防止重复审核与并发覆盖。
- 所有错误提示使用简体中文，不暴露 Prisma、SQL、JWT、堆栈或内部文件路径。

主要错误文案：

- “课程不存在”
- “只能选择自己创建的课件”
- “课件尚未生成完成”
- “请至少添加一个课件”
- “封面图比例必须为 4:3”
- “课程正在审核中”
- “审核状态已发生变化，请刷新后重试”

## 10. 变更范围

允许修改：

- `apps/web`
- `apps/api-core`
- `packages/database`
- 本设计与实施计划文档

不允许修改：

- `apps/ai-gateway`
- 支付、钱包、组织、多语言和复杂权限功能
- 与本功能无关的现有业务模块

需要新增 Prisma migration。seed 仅更新默认公开导航。必须保留并避开任务开始前已存在的未提交修改。
