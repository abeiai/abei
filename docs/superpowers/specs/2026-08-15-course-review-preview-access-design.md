# 课程资源待审预览与访问控制设计

**日期：** 2026-08-15

**状态：** 已确认方案，待规格复核

**范围：** `/c/{courseId}` 课程详情、作者预览、后台资源审核预览、公开课程详情 API

## 1. 目标

课程创作者和具有审核权限的管理员，应当在真实的 `/c/{courseId}` 前台课程界面中预览待审版本，不再使用另一套作者预览页面或后台 JSON 内容弹窗。

访问规则如下：

- 首次发布尚未审核通过：创作者和管理员看到待审课程；其他访客在同一稳定地址看到“资源审核中”。
- 已发布课程提交新版复审：创作者和管理员看到待审新版；其他访客继续看到上一版已审核内容。
- 已发布课程只有单个课件发生变化：课程继续公开，只锁定该待审课件，其他已审核课件继续可学习。
- 不存在的课程仍返回 404，不把任意 24 位 ID 伪装成审核中页面。

## 2. 方案比较与选择

### 方案一：同一公开地址按访问身份投影版本（采用）

`/c/{courseId}` 和对应详情 API 根据当前请求中的用户或管理员登录态，服务端选择待审工作版本、已审核版本或审核中占位状态。页面始终复用 `PublicCourseDetail`。

优点是预览与真实前台完全一致、课程 URL 稳定、没有重复页面；权限在 API 层收口，前端不能绕过。代价是公开详情接口需要支持可选身份识别和安全的联合响应类型。

### 方案二：保留独立作者和管理员预览路由

分别维护 `/dashboard/courses/{id}/preview` 和后台预览页，但复用前台组件。实现较直观，但地址和真实前台不同，容易产生展示分叉，后台与作者仍需维护不同入口。

### 方案三：签名预览链接

为每次审核生成短期签名 URL。适合向外部审稿人分享，但当前只有创作者和管理员两类固定身份，增加令牌签发、过期和泄漏治理没有必要。

## 3. 访问状态

课程详情读取返回以下联合状态：

- `AVAILABLE`：返回可渲染的课程数据。
- `REVIEWING`：只返回稳定课程 ID 和审核中状态，不返回标题、简介、封面、标签、作者或课件信息。
- 课程不存在：返回现有 404 中文错误。

`AVAILABLE` 的版本选择规则：

1. 当前用户是课程创作者，且存在工作版本时，选择工作版本。
2. 当前登录管理员具有现有后台审核权限，且存在工作版本时，选择工作版本。
3. 其他情况只选择已审核版本。
4. 没有已审核版本且访问者无权预览时，返回 `REVIEWING`。

项目当前只有 `SUPER_ADMIN` 管理员角色，因此有效、启用的管理员登录态即视为具有审核权限；本次不扩展权限矩阵。

## 4. 页面与入口

### 4.1 前台课程页

`/c/{courseId}` 保持现有面包屑、4:3 封面、课程标题、创作者、简介、标签和课程目录布局。

- 创作者或管理员查看待审版本时，沿用现有“审核中”状态标识。
- 普通访客访问首次待审课程时，页面返回 HTTP 200，并在公共站点框架内显示简洁的“资源审核中”状态，不渲染任何待审字段。
- 审核中占位页使用通用元数据，不把待审标题或简介写入 HTML 或 SEO 元数据。
- 已发布课程复审时，普通访客的页面和元数据都继续来自上一版已审核内容。

### 4.2 作者入口

课程编辑页和“我的课程”中的“作者预览”统一指向 `/c/{courseId}`。作者登录态由服务端识别，不再维护独立的视觉预览实现。

旧的 `/dashboard/courses/{id}/preview` 保留兼容跳转到 `/c/{courseId}`，避免已有书签失效；不再渲染第二套课程页面。

### 4.3 管理员入口

后台资源审核列表的“预览”打开真实 `/c/{courseId}` 页面：

- 课程版本审核直接使用审核请求的 `courseId`。
- 课件变更审核使用受影响课程作为预览上下文；只有一个课程时直接打开，多个课程时展示可选择的课程链接。
- 预览在新标签页打开，管理员可保留审核队列和 AI／人工审核弹窗状态。

后台不再把本地化 JSON 快照作为主要资源预览界面；结构化审核数据仍可供 AI 预审和审核差异逻辑使用。

## 5. 课件点击规则

- 已发布课程复审不再因为课程整体处于 `PENDING_REVIEW` 就禁用全部课件。
- 课件当前内容指纹与已审核指纹一致且课件仍可学习时，继续提供原生学习地址。
- 只有指纹不一致、首次尚未审核或被拒绝的课件不可点击，并显示对应审核状态。
- 创作者和管理员预览首次待审课程时，未审核课件仍不可通过课程目录进入匿名学习地址；本次不新增绕过课件审核的原生学习权限。

## 6. API 与安全边界

- 公开课程列表接口继续完全匿名，只列出至少审核通过一次的课程。
- 单课程详情接口允许匿名请求，但可选识别用户和管理员 Cookie。
- 身份识别失败按匿名访问处理，不向客户端暴露 JWT、刷新令牌或内部鉴权错误。
- 版本选择和字段裁剪必须在 NestJS 服务端完成，不能由 Next.js 页面拿到待审数据后再隐藏。
- `REVIEWING` 响应不得包含待审内容或内部外键。
- 作者身份以课程 `userId` 与当前登录用户 ID 的服务端比较为准。
- 管理员身份必须通过现有 `AdminAuthService` 校验。
- 管理员和用户 Cookie 可以共存；管理员身份只授予预览权限，不改变课程作者身份。
- 本次不新增数据库字段、migration、seed、签名令牌或新角色。

## 7. 错误处理

- 不存在的课程：404，“课程不存在或尚未发布”。
- 首次待审且无权访问：正常返回 `REVIEWING`，页面显示“资源审核中”。
- API 暂不可用：沿用课程加载失败处理，不伪装为审核中。
- 失效登录态：忽略该身份并按匿名访问；只有仍存在有效的另一类身份时才授予对应预览权限。

## 8. 测试与验收

按测试驱动方式实施，每个权限行为先写失败测试并确认失败原因，再写最小实现。

API 测试覆盖：

- 匿名访问首次待审课程只得到 `REVIEWING`，不泄露任何待审字段。
- 课程创作者访问首次待审课程得到工作版本。
- 非创作者登录用户仍只得到 `REVIEWING`。
- 有效管理员访问首次待审课程得到工作版本。
- 已发布课程复审时，匿名访客得到已审核旧版，创作者和管理员得到工作新版。
- 已发布课程复审不再锁定全部课件，只有真实待审课件不可点击。
- 不存在的课程继续返回 404。
- 公开课程列表不出现首次待审课程。

Web 测试覆盖：

- `REVIEWING` 状态渲染“资源审核中”且不渲染课程字段。
- 可访问课程继续使用 `PublicCourseDetail`。
- 待审占位元数据不包含待审标题和简介。
- 作者预览入口和后台课程审核预览指向 `/c/{courseId}`。
- 多个受影响课程的课件审核提供多个真实课程预览链接。
- 旧作者预览路由跳转到真实课程地址。

最终运行 API/Web 针对性测试、完整测试、类型检查、Lint 与生产构建；在具有作者或管理员登录态的浏览器中分别验证真实课程页，并以匿名状态验证审核中占位页。
