# 视频导学旧文案兼容与文案编辑设计

## 背景

视频导学拆分为“生成文案”和“合成语音”两个步骤后，新版使用 `narrationDraftTimeline` 表示可用于语音合成的文案草稿，并要求文案生成进度处于成功状态。旧课件已经保存了完整的 `narrationTimeline`、`narrationScript` 和逐句语音，但没有 `narrationDraftTimeline`，因此制作页错误显示为需要重新生成文案。

线上课件 `400e1ea319000517d6de5c84` 已验证具有 138 个完整的 `narrationTimeline` 节点和成功的文案进度，仅缺少新版草稿字段。兼容逻辑应识别这些既有数据，不能要求用户重新付费生成。

## 目标

1. 旧课件已有完整文案和语音时，制作页正确显示文案与语音已就绪。
2. 旧课件可以直接重新合成语音，不必先重新生成文案。
3. 已生成文案的课件支持编辑课程导入、每一句讲解和课程总结。
4. 编辑期间保留当前学习页面的文案与语音，只有新语音全部合成成功后才整体发布新版本。
5. 后台任务、课件归属和节点身份必须由服务端校验，前端不能直接覆盖整个课件内容。

## 非目标

1. 不编辑字幕时间轴或字幕文字。
2. 不提供分块讲解和词卡浮层的独立编辑器。
3. 不实现单句语音局部合成或旧音频自动复用。
4. 不在本次功能中自动重新生成随堂练习。

## 数据兼容

文案草稿读取采用以下优先级：

1. `narrationDraftTimeline` 存在且有效时使用该字段。
2. 否则，如果旧 `narrationTimeline` 存在且节点有效，则投影为文案草稿。投影保留节点 ID、类型、标题、字幕、时间轴、文案和讲解分块，但不把音频字段写入草稿。
3. 两者都不存在时才判定为没有文案。

文案就绪判断以“存在非空文案和有效草稿节点”为准。旧课件不因缺少新版进度字段而被误判；正在排队或运行的后台任务仍由现有任务租约逻辑限制操作。

Web 端解析课件内容时采用同样的优先级，使按钮状态、文案编辑器和语音合成入口保持一致。API 端的点数预估与语音合成也通过统一的兼容读取函数获取草稿。

## 双版本发布

课件内容区分两个版本：

- `narrationDraftTimeline`：制作页正在编辑、准备合成的文案草稿。
- `narrationTimeline`：学习页面当前使用的已发布文案和语音。

保存人工编辑时：

1. 写入新的 `narrationDraftTimeline` 和汇总后的 `narrationScript`。
2. 保留原 `narrationTimeline`、旧音频地址和当前学习页面，不立即中断分享页面。
3. 写入 `narrationAudioStale: true` 和文案更新时间，制作页显示“文案已修改，语音待重新合成”。
4. 清除已结束的语音合成任务进度和任务租约，允许用户重新提交语音合成。

新语音全部生成并通过 R2 校验后：

1. 现有语音合成成功事务用新时间线替换 `narrationTimeline`。
2. 清除 `narrationAudioStale`。
3. 学习页面一次性切换到新文案和新语音。

如果合成失败，旧学习页面继续可用，草稿和失败进度保留，用户可以在同一课件上重试。

## 文案保存 API

新增用户接口：

```text
PATCH /api/video-guide/lessons/:id/narration-script
```

请求只提交节点 ID 和编辑后的文案：

```json
{
  "nodes": [
    {
      "id": "s_001",
      "script": "编辑后的讲解文案"
    }
  ]
}
```

服务端处理流程：

1. 验证用户登录和课件归属。
2. 锁定课件记录，拒绝在文案、语音、字幕或练习任务运行时保存。
3. 通过兼容读取函数取得当前草稿，验证请求节点集合与服务端节点集合完全一致，禁止新增、删除、重复或替换节点 ID。
4. 所有文案必须去除首尾空白且不能为空，并限制单节点和总文案长度。
5. 未修改节点保留原 `chunks` 和词卡 overlay。
6. 修改节点折叠为一个人工编辑 chunk，文本使用新文案，overlay 置空，避免旧分块或旧词卡与新文案不一致。
7. 保存新草稿、汇总文案、失效标记和更新时间，同时保留已发布语音时间线。
8. 返回更新后的完整课件。

## 编辑弹窗

“导学文案”步骤在文案就绪后同时显示“编辑文案”和“重新生成文案”。

弹窗采用单节点编辑：

1. 顶部显示“文案编辑”、当前位置和关闭图标。
2. 导入节点上方显示只读的“课程导入”。
3. 逐句节点上方显示原字幕句子，只读且完整换行。
4. 总结节点上方显示只读的“课程总结”。
5. 下方 textarea 编辑当前节点的讲解文案。
6. 底部固定显示“上一句”“下一句”和“确认保存”。首尾节点禁用相应方向按钮。
7. 切换节点时保留本地编辑结果，不逐句请求服务器。
8. 确认时一次提交全部节点；存在空文案时停留在对应节点并给出中文校验提示。
9. 保存成功后刷新当前课件，显示“文案已修改，语音待重新合成”。

移动端弹窗使用接近全屏的高度，正文区域滚动，底部操作栏固定，按钮和文本不得因长字幕产生横向溢出。

## 状态与按钮

制作页状态规则：

- 只有旧 `narrationTimeline`：识别为文案已就绪、语音已就绪。
- 有 `narrationDraftTimeline` 且 `narrationAudioStale` 为真：文案已就绪，显示“语音待重新合成”。
- 有草稿但没有已发布时间线：文案已就绪，学习页尚未完成，允许首次合成语音。
- 语音合成运行中：禁用编辑文案、重新生成文案和重复合成。
- 语音合成失败：保留草稿和旧学习页，允许重试。

## 错误处理

1. 课件不存在或不属于当前用户时返回中文的不存在提示。
2. 后台任务运行时返回“当前课件正在生成中，请稍后再编辑文案”。
3. 节点集合不一致时返回“文案已发生变化，请刷新后重试”。
4. 空文案、超长文案和重复节点使用请求参数错误，不暴露内部数据库信息。
5. 保存使用课件行锁，避免编辑结果覆盖刚完成的后台任务。

## 测试

API 测试覆盖：

1. 旧 `narrationTimeline` 可以投影为草稿并通过文案就绪判断。
2. 新 `narrationDraftTimeline` 优先于旧发布时间线。
3. 保存编辑保留发布时间线和旧音频，写入草稿与失效标记。
4. 修改节点折叠 chunk，未修改节点保留原 chunk 和 overlay。
5. 缺失、重复、未知和空文案节点被拒绝。
6. 活跃后台任务和非课件所有者不能保存。
7. 新语音成功后清除失效标记。

Web 测试覆盖：

1. 旧课件被识别为文案已就绪。
2. 编辑器按导入、逐句、总结顺序建立状态。
3. 上一句和下一句保留尚未提交的修改。
4. 空文案定位到错误节点。
5. 保存请求只提交节点 ID 和文案。

验收页面：

```text
/media-tutor
```

使用旧课件 `400e1ea319000517d6de5c84` 验证其不再显示为需要生成文案，并可以打开包含导入、逐句讲解和总结的文案编辑弹窗。
