# 英文带学节点音频同步设计

## 目标

彻底移除英文带学中基于文本长度估算、全局缩放和原文比例拆分的同步方式。句子与词语高亮必须由当前正在播放的教学节点直接决定，不再根据整条音频的 `currentTime` 猜测。

## 已确认决策

- 允许现有英文带学材料重新生成节点音频。
- 新材料默认生成节点音频，不再生成单条完整讲解音频作为主播放源。
- 旧单条音频保留到新节点音频全部生成成功；失败时继续使用旧音频，不写入半成品。
- 词语高亮采用“教学焦点同步”：老师讲解该词语的整个节点期间持续标红。
- 不修改数据库 schema，节点数据继续存入材料 `content` JSON。

## 根因

当前实现存在四个不可通过比例修正消除的误差源：

1. 时间轴由原文、讲解摘要、语法说明和词语说明字数估算，实际 TTS 只朗读最终讲解文稿。
2. 完整音频包含导入与总结，旧时间轴没有独立的导入和总结节点。
3. TTS Provider 返回 URL 和字符数，但当前样本没有返回真实时长；数据库保存 260 秒，实际 MP3 为 189.288 秒。
4. 旧材料将四个大段按英文原文字数比例拆为二十三句，中文讲解时长与英文原文字数没有稳定比例。

因此必须从“时间估算驱动”改为“音频节点身份驱动”。

## 数据结构

材料 `content` 新增：

```ts
interface EnglishNarrationTimelineV2 {
  version: 2;
  nodes: EnglishNarrationNode[];
}

interface EnglishNarrationNode {
  id: string;
  type: "INTRO" | "SENTENCE" | "SUMMARY";
  sentenceId: string | null;
  chunkType: "INTRO" | "CONTEXT" | "WORD" | "PHRASE" | "GRAMMAR" | "TRANSLATION" | "SUMMARY";
  script: string;
  focus: {
    pointId: string | null;
    text: string;
  } | null;
  audioTaskId: string;
  audioUrl: string;
  durationMs: number;
}
```

`sentenceId` 决定高亮哪一句；`focus.text` 决定句内标红内容。`INTRO` 和 `SUMMARY` 节点不高亮正文。

## 节点文稿生成

后台增加 AI 场景 `english-guided-study-narration-nodes`。输入使用材料已经确认的标题、水平、摘要、逐句原文、逐句带学文稿和词语点，不重新生成练习题。

模型输出：

```json
{
  "intro": { "script": "导入文稿" },
  "sentences": [
    {
      "sentenceId": "s1",
      "chunks": [
        { "type": "CONTEXT", "script": "语境讲解", "focusPointId": null },
        { "type": "PHRASE", "script": "短语讲解", "focusPointId": "p1-1" },
        { "type": "GRAMMAR", "script": "语法讲解", "focusPointId": null }
      ]
    }
  ],
  "summary": { "script": "总结文稿" }
}
```

解析器必须验证：

- 每个原文句子有且只有一个对应 `sentenceId`。
- 每句至少一个、最多四个教学节点。
- `focusPointId` 必须属于对应句子的现有词语点。
- 节点 `script` 不得为空，且组合后覆盖原带学文稿的主要教学信息。
- 解析失败时返回中文错误，不回退到估算时间轴。

## 音频生成

复用视频导学 `synthesizeNarrationTimeline` 的逐节点 TTS 模式：

1. 按顺序为导入、句子教学节点和总结分别生成音频。
2. 子节点使用外部计费 TTS 任务，单个任务不独立扣点。
3. 按所有节点脚本字符总量进行一次报价、一次冻结和一次结算，避免多个任务重复触发最低消费。
4. 每个节点完成后使用 Provider 时长；Provider 不返回时长时，服务端使用 `ffprobe` 读取真实 `durationMs`。
5. 所有节点成功后，在单个数据库事务中写入 `narrationTimelineV2`、总时长和首节点兼容 URL。
6. 任一节点失败时删除或忽略本批半成品，保留材料原音频和原内容。

节点任务默认串行或限制为三路并发，避免对 TTS Provider 形成突发压力。音频总字符数与当前完整文稿接近，计费不因节点数量增加。

## 播放器

播放器状态改为：

```ts
currentNodeIndex: number
nodeCurrentTime: number
nodeDuration: number
```

同步规则：

- 当前节点为 `SENTENCE`：高亮 `sentenceId` 对应原句。
- 当前节点有 `focus`：在该句中标红 `focus.text`。
- 当前节点为 `INTRO` 或 `SUMMARY`：正文不高亮，播放器显示“导入讲解”或“总结讲解”。
- 当前音频 `ended`：进入下一节点并播放。
- 播放前预加载后两个节点，降低切换停顿。

总进度使用节点真实时长累计：

```text
已完成节点时长之和 + 当前节点时间
-----------------------------------
所有节点真实时长之和
```

拖动总进度条时，根据累计时长定位目标节点和节点内时间，不再查找估算句子区间。

## 句级控制

- 上一句：跳到上一个不同 `sentenceId` 的首节点。
- 下一句：跳到下一个不同 `sentenceId` 的首节点。
- 重听本句：回到当前句首节点。
- 单句循环：当前句最后一个节点结束后回到当前句首节点。
- 全文循环：总结节点结束后回到导入节点。
- 学习进度：一个句子的所有节点播放完成后，才记为完成一句。

## 现有材料迁移

现有材料不自动批量执行，以免未经用户操作消耗点数。生成区对旧材料显示“重新生成精准讲解音频”：

1. 保留原音频可试听。
2. 用户确认音色、速度和费用后触发节点音频生成。
3. 生成成功后材料切换到 `version: 2`。
4. 生成失败时显示中文原因，原分享链接和原音频继续可用。

学习页遇到旧材料时继续使用旧播放器，并提示该材料需要重新生成精准音频；不再把四个旧段落伪拆成二十三个看似精确的时间段。

## 编辑行为

- 修改导入：只使导入节点失效。
- 修改某句带学文稿：只使该句节点失效。
- 修改音色、速度：所有节点重新生成。
- 修改原文或水平：材料文稿和所有节点全部重新生成。

第一版可以整批重新生成；节点级增量生成作为同一数据结构上的后续优化，不阻塞本轮落地。

## 错误处理

- AI 节点覆盖不完整：`AI 未完整生成逐句讲解节点，请重新生成`。
- 某节点 TTS 失败：`第 N 句讲解音频生成失败，原音频已保留`。
- 无法读取真实时长：节点仍可依赖浏览器元数据播放，但本批不标记为可分享完成状态。
- 分享页发现节点 URL 失效：材料不可开始播放，并提示重新生成，不静默回退到错误时间轴。

## 验收标准

1. 导入和总结期间不高亮任何正文句子。
2. 每个句子教学节点只高亮其 `sentenceId` 对应句子。
3. 词语节点整个播放期间只标红该节点 `focus.text`。
4. 任意倍速、暂停、继续、拖动、上一句、下一句后，高亮仍由当前节点确定。
5. 单句循环不会越过当前句的节点范围。
6. 数据库总时长与各节点真实时长之和一致，误差不超过 100 毫秒。
7. 现有材料重新生成失败时，原音频、原分享页和原内容不受影响。
8. 桌面和移动端都能无感连续播放节点；节点切换不改变页面布局。

## 测试范围

- 节点 JSON 严格解析与全文覆盖测试。
- `focusPointId` 归属校验测试。
- 节点批量 TTS 成功、部分失败、原子切换测试。
- 聚合计费测试，确保不会按节点重复最低扣费。
- 真实时长探测和累计进度映射测试。
- 上一句、下一句、重听、单句循环、全文循环状态测试。
- 旧材料重新生成成功与失败保留旧音频测试。
- 桌面和移动端浏览器播放、高亮与拖动验证。
