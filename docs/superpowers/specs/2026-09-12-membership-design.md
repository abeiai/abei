# 会员收费与权益设计草案

状态：用户已确认一次性赠点、完整购买周期结束清零，进入实施。

## 范围与现状

保留现有点数包，增加多等级会员及日、周、月、季、年价格。沿用支付宝、微信支付，由用户主动购买或续费，不接自动扣款。

现有 BillingProduct 已有订阅模式标记，但 PaymentService 结算仍将所有商品点数计入永久钱包；当前没有会员周期与权益兑现机制。AI、语音、视频导学、英语导学、字帖都有直接钱包扣减路径，需要统一接入周期点数分配。学习者目前主要受账号编号上限约束，没有会员额度。

允许修改 apps/web、apps/api-core、packages/database 及相关 docs。不得修改 ai-gateway、部署配置、真实环境变量及无关功能。保留工作区所有已有改动，尤其 schema 和 AI/英语导学服务中的未提交修改。需要新增兼容 migration；不覆盖现有数据，不重置数据库。不自动创建上架会员价格；seed 不必更新。

## 商品与定价

后台维护等级名称、等级权重、上下架状态、排序和权益。每个等级可独立启用五种付费周期；每种周期保存原价、折扣、可选手动优惠价、最终价格和赠送点数。

自动优惠价为原价乘折扣，按人民币分四舍五入；手动优惠价优先，清空后恢复自动计算。金额以整数分计算或 Decimal 存储，禁止依赖浮点金额结算。禁止负价格、超过原价的优惠价和非法折扣。

每百点价格 = 最终实付价 ÷ 本次付费涵盖的赠送总点数 × 100。赠点为零时显示“不适用”。此数值仅为套餐价格与赠点的折算，不声称其他权益免费或无价值。

订单保存等级、周期、价格、赠点和权益快照；后台之后改价不改变已创建订单或已购周期。停用等级阻止新购，不中止已付费权益。

## 周期规则（已确认）

按用户确认的购买周期发放：日付一次发放当日周期点数，年付一次发放全年周期点数，结束时清零。后台为各周期单独设置赠点，避免不同周期获得相同点数的歧义。

日/周按购买生效时刻加 1/7 天；月/季/年按自然日历加 1/3/12 月，月底取目标月最后一天，保存 UTC 时间、按北京时间展示。周期为左闭右开区间，到期时刻起不可再使用该周期点数。

首次付款成功立即生效。同等级提前续费排入下一周期，下一周期生效时发点，不提前混入当前余额。跨等级购买也在当前周期结束后生效，前台明确显示生效日期；本次不增加中途补差价与退款计算。

## 会员点数与账务

采用独立会员周期余额和分配记录，保留原有永久购买点数。每次消费先分配当前有效会员点数，不足部分扣购买点数；并发扣款在同一事务内串行化或条件更新，禁止超扣。

冻结、结算、释放和退款均记录原始点数来源及会员周期。任务失败时购买点数退回购买余额；会员点数只退回尚未到期的原周期，已到期部分记录失效，不转成永久点数，也不转入新周期。周期结束时未冻结余额清零，冻结中的任务允许依原分配结算，释放后按到期规则作废。

订单结算与开通会员在同一事务中完成，支付回调、主动查单、重试不能重复开通或发点。周期激活、失效及流水均有唯一幂等键。到期正确性依赖服务端实时有效期判断，后台清理任务只辅助生成到期记录，不作为鉴权唯一依据。

用户中心显示会员等级、起止时间、待生效周期、会员剩余点数、购买点数、合计可用点数及对应流水。旧点数包支付和永久余额语义保持兼容。

## 权益

- 资源中心：有效会员免费访问所有已发布资源。现有非会员免费资源保持免费；未来单资源收费统一先判断会员豁免，本次不新增资源收费商品。草稿、未发布和管理功能仍受原权限控制。
- 场景应用：配置最低会员等级、可选提前开放截止时间。服务端在实际调用入口校验，不能仅隐藏按钮。学习者权限取主账号会员资格与原有场景授权的交集，不绕过既有授权。
- 存储空间：每等级配置容量，展示权益；不统计已用量、不拦截上传、不自动删除到期文件。
- 学习者：配置会员可启用学习者数量及非会员默认额度，创建和恢复均检查额度。到期或降级不删除已有学习者和学习记录；超额时阻止新增或恢复，既有学习者继续可用。默认额度需后台可配置，不暗中批量停用老账号。
- 扩展权益：保留具有稳定编码、类型和值的权益项结构，展示文案与实际能力分开；新增权益可扩展，不把任意 JSON 当可执行权限规则。

## 页面和实施顺序

1. 后台会员等级与各周期价格、赠点、存储、学习者额度、扩展权益配置，前台会员价格展示。
2. 复用现有支付页实现会员购买，用户中心展示已生效及待生效会员。
3. 全部个人点数消费入口接入会员优先扣减、冻结和退回；企业钱包不纳入个人会员赠点。
4. 场景后台会员门槛、服务端校验、学习者额度和资源权益接入。
