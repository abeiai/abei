# 视频导学媒体资产级识别音频缓存设计

## 背景

生产服务器从 Cloudflare R2 读取约三百 MB 的视频时，实际吞吐约为每秒一百一十 KB。现有字幕链路在任务开始后才让 ffmpeg 通过远程 URL 读取完整视频并提取音频，默认三十分钟预处理超时不足以覆盖四十至六十分钟的远程读取时间，因此大文件会在进入阿里云语音识别前稳定失败。

## 目标

1. 新上传媒体在本地文件仍可用时生成十六千赫兹、单声道、四十八 kbps AAC 识别音频。
2. 识别音频绑定到去重后的媒体资产，由所有引用该媒体的课件共享。
3. 生成或重新生成字幕时直接复用缓存，不再重复下载完整视频。
4. 历史媒体首次生成字幕时保留兼容回退，成功后写回缓存，以后直接复用。
5. 缓存校验失败时不把坏地址交给语音识别，并保留明确的重试和失败状态。

## 方案选择

采用媒体资产级缓存，不采用课件 JSON 缓存或单纯延长超时。

- 媒体资产级缓存与现有 SHA-256 去重模型一致，一份媒体只生成一份识别音频。
- 课件 JSON 缓存会在多用户或多课件引用同一媒体时重复存储，并增加误删风险。
- 单纯延长超时只能掩盖慢速远程读取，重新生成字幕时仍会重复消耗时间和带宽。

## 数据模型

在 `VideoGuideAsset` 增加以下可空字段：

- `asrObjectKey`：R2 中稳定的识别音频对象 key，唯一索引。
- `asrMimeType`：固定为 `audio/mp4`，为后续格式演进保留字段。
- `asrSizeBytes`：识别音频实际字节数。
- `asrPreparedAt`：缓存生成完成时间。

字段必须同时存在才视为缓存可用。历史记录全部为空，不需要离线迁移。

## 对象命名

稳定缓存使用媒体内容哈希生成对象 key：

```text
video-guide/asr-cache/sha256/{hash 前两位}/{完整 hash}.m4a
```

对象 key 不包含用户名、原始文件名或签名参数。相同媒体并发生成时会写入相同内容和相同 key，PUT 操作保持幂等。

现有 `video-guide/asr-temp/` 只保留给无法关联到媒体资产的兼容任务，仍按原规则清理。

## 新媒体上传流程

1. 校验文件类型、大小并计算现有 SHA-256 内容哈希。
2. 命中已有媒体资产时直接复用；已有识别音频缓存也随资产复用。
3. 未命中时，从上传缓冲区生成网页播放文件和轻量识别音频。
4. 分别上传网页播放文件与稳定识别音频到 R2。
5. 对识别音频执行字节范围读取校验。
6. 创建媒体资产时同时写入识别音频字段，再创建用户引用。

轻量音频是字幕生成的必要派生资产。视频或音频不存在有效音轨、ffmpeg 失败、R2 上传失败或校验失败时，本次媒体转换返回简体中文错误，不创建半完成的新媒体资产。已经存在的共享媒体资产不受本次失败影响。

## 历史媒体兼容流程

历史媒体资产没有识别音频字段时，字幕任务沿用远程提取流程，但作以下调整：

1. 预处理总超时默认提高到九十分钟，仅用于历史兼容回填。
2. 提取成功后不再上传任务级临时对象，而是按媒体哈希上传稳定缓存。
3. R2 校验成功后以条件更新写回媒体资产字段。
4. 同一媒体并发回填允许重复计算，但最终写入同一稳定 key，不产生重复对象。
5. 回填完成后当前字幕任务立即使用该缓存提交语音识别。

历史回填属于一次性成本。后续重新生成字幕或其他课件引用该媒体时不再读取完整视频。

## 字幕任务复用流程

1. 根据课件的 `mediaStorageKey` 查找 `VideoGuideAsset`。
2. 缓存字段完整时生成短期签名 URL，并执行一字节范围读取校验。
3. 校验通过后把缓存信息写入字幕任务检查点，标记为可复用对象。
4. 提交阿里云识别并沿用现有可恢复轮询。
5. 字幕成功、失败或课件删除时都不删除可复用缓存。
6. 缓存校验失败时清空失效字段并进入历史回填，不向模型提交坏 URL。

字幕检查点增加 `asrReusable` 布尔值。只有该值为 `false` 的任务级临时对象才执行现有成功或失败清理。

## 生命周期与删除

识别音频属于媒体资产，不属于单条课件。删除课件或某个用户引用时不得直接删除缓存，否则会破坏其他课件和用户的引用。

本次改动沿用现有媒体资产保留策略，不新增资产垃圾回收任务。以后执行 `refCount = 0` 的媒体资产垃圾回收时，必须在删除媒体对象的同时删除 `asrObjectKey`，再删除数据库资产记录。

## 故障处理

- 本地提取失败：媒体上传失败并返回“未能生成语音识别音频，请确认文件包含有效音轨”。
- 稳定缓存上传失败：媒体上传失败，不创建数据库资产记录。
- 稳定缓存预检失败：不写数据库字段并返回错误。稳定 key 不在请求失败路径删除，避免与同一媒体的并发上传互相误删；下一次相同上传会幂等覆盖该 key。
- 已有缓存失效：清空缓存字段后重新回填。
- 历史回填超时：字幕任务失败并释放冻结点数，保留可重新提交状态。
- 阿里云识别失败：保持现有重试、检查点和点数释放逻辑，缓存不删除。

日志记录媒体资产 ID、缓存阶段和错误类型，不记录签名 URL、R2 密钥或用户凭据。

## 验收标准

1. 新上传视频在返回成功前已经生成、上传并校验识别音频缓存。
2. 同一媒体秒传后复用同一个 `asrObjectKey`。
3. 字幕任务命中缓存时不调用远程视频 ffmpeg 提取。
4. 历史媒体首次生成成功后写回缓存，第二次生成直接复用。
5. 可复用缓存不会在字幕成功或失败后被删除。
6. 无音轨文件、R2 上传失败和缓存校验失败均返回中文错误且不产生半完成资产。
7. Prisma migration、API Core 相关单元测试、集成测试、类型检查和生产构建通过。
8. 生产部署后，新上传测试媒体的字幕任务能在一分钟内离开“准备音频”阶段；历史大文件首次回填不再受三十分钟超时限制。
