# 学习场景 TTS 精确计费设计

## 目标

英文带学、古诗文带学、开卷导读和视频导学的讲解语音，以及英文/古诗文全文诵读，必须按实际提交给 TTS 服务的最终文本字符数核算点数。编辑已有语音的文稿时，只计算需要重新合成的节点。上传全文诵读音频不执行 TTS，继续保持 0 点。

## 当前问题

- 带学讲解语音按带换行的整篇 `narration` 计数，实际按独立节点合成。
- 全文诵读按换行拼接后的单元文本计数，实际逐单元合成。
- 开卷导读实际会移除自然段空行，整稿计数包含了这些分隔字符。
- 视频导学实际 TTS 会清理 Markdown 标题、列表标记和多余空行，并截断超长节点，当前报价按处理前文稿计数。
- TTS 点数确认界面仍显示“预计消耗”，但确认文稿已经能够确定实际合成字符数。

## 统一规则

1. 每个业务模块必须先构造最终 TTS 节点清单，报价和合成都读取同一清单。
2. 计费字符数为 `sum(node.text.length)`，不得通过带分隔符的整稿字符串计算。
3. 计费修订值必须包含最终节点文本和语音设置；确认后节点或设置变化时拒绝旧报价。
4. 点数继续采用各场景现有的基础点数加每千字符阶梯规则，只修正字符输入和确认语义。
5. 编辑文稿只报价并合成目标节点；未变化时不扣费。
6. 视频导学保留失败后按已完成节点结算及断点续作不重复收费的规则。
7. 上传全文诵读音频不收取 TTS 费用，使用独立 ASR 计费项目：按服务端确认的音频时长，每起算一分钟 2 点；成功结算，失败释放冻结点数。

## 兼容性

- API 的 `estimatedCredits` 字段暂时保留，避免影响现有客户端；对 TTS 操作它表示已确认文本对应的准确点数。
- AI 文稿生成等结果尚未确定的操作仍使用“预计消耗”；上传音频 ASR 按已确认时长显示“本次消耗”。
- 不修改数据库结构、点数单价环境变量或已有流水幂等键格式。

## 验收

- 带学讲解语音、局部编辑、全文诵读和开卷导读的计费字符与实际 TTS 入参逐字符一致。
- 视频导学报价使用清理、截断后的实际 TTS 文本，并继续正确处理断点计费。
- 上传音频按服务端真实时长每起算一分钟 2 点，重复轮询不重复结算，识别失败自动释放。
- TTS 确认弹窗显示“本次消耗”；非 TTS 操作继续显示“本次预计消耗”。
