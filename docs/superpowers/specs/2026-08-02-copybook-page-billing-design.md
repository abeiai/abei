# 字帖按页扣点设计

## 目标

字帖生成改为按实际生成页数收费：无水印每页 2 点，有水印每页 5 点。前端确认提示、服务端实际扣点、钱包流水和字帖记录必须保持一致。

## 费用规则

- 实际页数取经过 Layout 解析器校验后的 `pages.length`，单页 Layout 计为 1 页。
- 任意一页存在有效文本水印或图片水印时，整份字帖按带水印规则收费。
- 无水印费用：`页数 * 2`。
- 有水印费用：`页数 * 5`。
- 前端提示：
  - `本次生成字帖10页，需消耗20点，确认生成将自动扣除。`
  - `本次生成带水印字帖10页，需消耗50点，确认生成将自动扣除。`

## 服务端信任边界

服务端不采信前端传入的点数。`CopybooksService` 从 Layout 计算页数、水印状态和费用，并将计算结果用于余额预检、钱包扣点、字帖记录和响应。旧客户端携带的 `credits` 字段仅用于兼容请求格式，不参与计费。独立的钱包字帖扣费接口不再对客户端开放，扣费只能从字帖生成服务内部发起。

有效水印以 Layout 解析器的结果为准：只有包含非空文本的可见文本水印，或包含合法图片地址的可见图片水印，才视为带水印。

## 幂等与失败处理

- 相同 `requestId` 已生成时返回原记录及原扣点数，不重复生成或扣点。
- 相同幂等键已有流水时必须校验流水类型和扣点金额，金额不一致直接返回冲突。
- 余额不足时在渲染和上传前拒绝生成。
- 字帖记录与钱包扣点在同一数据库事务中提交；事务失败时记录与扣点同时回滚，并清理本次上传的 R2 文件。

## 前端交互

前端根据当前 Layout 页数和有效水印状态即时显示确认提示。生成请求不再提交费用；成功消息使用服务端响应的实际扣点数。

## 测试

- 服务端定价单元测试覆盖单页、多页、有效水印、无效水印和伪造低费用请求不影响服务端计费。
- 前端定价单元测试覆盖提示所需的页数、费用和水印状态。
- 运行字帖相关测试、API/Web 类型检查及构建。

## 数据库

无需 migration。现有 `CopybookRecord.credits` 和 `CopybookRecord.pageCount` 字段继续保存本次生成的实际费用与页数。
