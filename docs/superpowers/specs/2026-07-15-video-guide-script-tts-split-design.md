# 视频导学文案与语音分步生成设计

## 目标

把现有一次完成的“导学文案生成 + 逐句语音合成”拆成两个独立异步步骤。两个步骤分别估算和确认点数、分别显示持久化进度、分别支持失败后在同一课件记录上重试。

## 已确认规则

- 生成文案完成后，才可以点击合成语音。
- 文案完成、语音未完成时，课件不开放学习和分享。
- 文案完成后可以生成随堂练习。
- 语音全部生成、上传 R2 并校验成功后，课件才标记为 `SUCCEEDED`。
- 所有操作继续使用当前课件 ID，失败重试不创建新课件记录。
- 两个步骤均为后台异步任务，提交后用户可以关闭页面，回来后继续查看进度。

## 状态模型

课件继续使用现有 `VideoGuideLesson.status`，不修改数据库结构：

- 文案任务排队或运行：课件状态为 `QUEUED` 或 `GENERATING`。
- 文案任务成功：课件状态回到 `DRAFT`，`content.narrationGenerationProgress.status = SUCCEEDED`。
- 语音任务排队或运行：课件状态为 `QUEUED` 或 `GENERATING`。
- 语音任务成功：课件状态为 `SUCCEEDED`。
- 任一步骤失败：课件状态为 `FAILED`，对应进度记录失败信息；课件仍可在原记录上重试。

`content` 新增独立字段：

```ts
narrationTtsGenerationJob
narrationTtsGenerationProgress
narrationDraftTimeline
```

现有字段含义调整如下：

- `narrationGenerationJob` 和 `narrationGenerationProgress` 只代表文案生成。
- `narrationDraftTimeline` 保存不含音频地址的导入、逐句讲解、总结节点。
- `narrationTimeline` 只保存已经通过 R2 校验的最终语音时间线。
- `narrationAudioProgress` 保留逐节点生成、上传、校验状态。

## 文案生成

现有 `POST /video-guide/lessons` 保持为文案生成入口，避免前台和历史调用大范围迁移。该入口只估算并冻结 `GUIDE_CONTENT` 点数，生成逐句文稿后立即保存：

- `narrationDraftTimeline`
- `narrationScript`
- AI 模型、供应商和任务 ID
- 文案成功进度

成功时释放或结算本次文案费用，将课件状态设为 `DRAFT`。文案任务不得调用 TTS。

重新生成文案时清除旧的最终语音时间线、语音进度和旧练习，避免学习页继续使用与新文案不一致的内容。R2 历史对象本次不主动删除，由后续对象清理策略统一处理。

## 语音合成

新增接口：

```text
POST /video-guide/lessons/:id/narration-audio/estimate
POST /video-guide/lessons/:id/narration-audio
```

只有同时满足以下条件才允许提交：

- 课件属于当前用户。
- 文案任务已成功。
- `narrationDraftTimeline` 存在且至少有一个有效讲解节点。
- 当前没有其他视频导学生成任务运行。

语音费用按已生成文稿的真实字符数估算，只包含 `TEACHER_NARRATION_TTS`。用户确认后创建独立 `NARRATION_TTS` 持久化任务，读取 `narrationDraftTimeline`，逐节点调用现有视频导学 TTS 与 R2 强制持久化流程。

全部节点上传并校验成功后，写入最终 `narrationTimeline` 和兼容音频字段，将课件标记为 `SUCCEEDED` 并结算语音费用。失败时保留逐节点进度、释放本次冻结点数，并允许在当前记录上重新合成。

## 随堂练习

随堂练习的可用条件从“课件已完成”调整为“文案已成功并存在有效文稿”。它可以与待合成的语音处于同一课件中，但不得和文案重新生成并发执行。

## 前台交互

右侧流程拆成两个紧凑步骤：

1. 导学文案：按钮为“生成文案”或“重新生成文案”，单独弹出文案费用确认，显示文案异步进度。
2. 讲解语音：选择多语种音色，按钮为“合成语音”或“重新合成语音”。文案未完成时禁用；点击后单独弹出语音费用确认，显示逐段合成进度。

文案完成时提示“文案已生成，可以继续合成语音或生成随堂练习”。语音完成时提示“导学课件已完成，可以进入学习或分享”。历史列表在中间状态显示“文案已完成”或“语音生成中”，避免误报整个课件已完成。

## 恢复与并发

- 后台恢复巡检同时识别 `NARRATION` 与 `NARRATION_TTS` 任务。
- 每个任务使用独立 job、progress、operation key 和冻结流水。
- 同一课件同一时间只允许一个视频导学生成操作运行。
- 恢复任务必须复用原 operation key，防止重复冻结和重复扣点。
- 文案和语音失败后均保留原课件、失败进度和可重试输入。

## 验收标准

- 文案费用弹窗只显示内容生成费用，提交后接口快速返回并持续显示可恢复进度。
- 文案成功后课件仍不可学习或分享，但语音和练习按钮可用。
- 语音费用基于实际文稿字符数，语音提交后独立显示进度。
- 语音成功前学习接口拒绝访问；成功且所有节点为 R2 CDN 地址后开放。
- 任一步骤失败后再次点击都覆盖当前课件记录，不新增历史项。
- 页面刷新或关闭重开后，两个步骤的状态和进度均可恢复。
