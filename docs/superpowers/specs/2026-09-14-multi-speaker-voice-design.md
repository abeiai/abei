# 语音合成多人配音设计

## 1. 目标与确认记录

在 `/experience/voice` 增加多人配音，保留默认单人模式及现有单人生成行为。多人模式支持角色识别、跨模型音色绑定、逐段语速和停顿、总费用确认、完整音频合并，以及单句修改重合成。

用户已确认界面与处理方案，并确认以下计费规则：

- 按每句实际匹配的模型分别报价，汇总后由用户确认。
- 部分失败时保留成功音频，只扣成功句子的费用，释放失败部分的冻结点数。
- 修改单句后只重新报价、确认并生成这一句。
- 修改停顿、重试合并或 R2 保存，不重复收取语音合成费用。

截图仅作交互参考，不照搬截图中的大段落卡片或保留正文角色前缀的行为。

## 2. 范围与限制

允许修改：

- `apps/web/src/app/experience/voice/`、语音工作台组件、相关 API 封装与测试。
- `apps/api-core/src/audio/`、相关测试；音频模块内增加独立的多人任务、计费协调、存储和合并单元。
- `packages/database/prisma/schema.prisma`、本次新增 migration；仅在生成类型导出确有需要时修改数据库包导出。
- `docs/superpowers/specs/`、`docs/superpowers/plans/` 中本需求的文档。

不修改词典、英文带学、古诗文、打字练习、CMS、支付和登录业务；可以读取既有计费与身份校验辅助代码并复用其接口。不升级依赖，不发布线上，不替换用户已有未提交改动。

需要新增、非破坏性数据库 migration；不需要 seed。服务端已有 FFmpeg，无需引入手写音频解码或拼接器。使用现有 Next.js、NestJS、Prisma 和 S3 兼容 R2 配置。

## 3. 界面

### 3.1 工作台与模式

保持三栏工作台：左栏历史 `292px`，中栏 `minmax(0, 1fr)`，右栏设置 `360px`；间距与内边距均为 `20px`，背景 `#f6f6f5`。移动端按历史、内容、设置自然堆叠，不产生横向溢出。

右栏顶部提供单人配音与多人配音分段切换控件，默认单人。两种模式分别保留草稿；切换不清空另一模式正文，不自动发起合成。

### 3.2 多人正文

中栏是一块整体编辑区：所有对话段落共用外框，不逐句创建独立面板或大文本卡片。每段左侧为小头像和设置图标，正文采用无独立外框的可编辑区域。设置图标选择当前段落，其参数在右栏展示。

正文不包含已识别的角色前缀。头像的可访问名称与 tooltip 展示角色名、绑定音色；角色名在右栏映射列表中可见。段落增加、删除、试听、重新合成采用常见图标并提供中文 tooltip，键盘可操作。中栏不展开参数表单或说明性长文案。

提供整体文本粘贴与识别入口；识别后仍可编辑每段正文及其角色归属。保留原始草稿，避免重复识别不可逆地丢失用户文本。

### 3.3 右栏设置

多人模式的右栏包含角色映射、当前段落设置、输出设置和扣费空间。

- 角色映射复用现有 VoicePicker 和头像资源，允许多个文本角色分别绑定音色，也允许共用同一音色。
- 不提供手动模型选择。前后端均复用现有自动匹配规则；模型名称仅用于能力判断和费用明细，不作为可选字段。
- 当前段落可以选择文本角色、设置语速及段尾停顿。语速范围随匹配模型变化，服务端再次校验；不将不支持的值静默截断。
- 段尾停顿默认 `0.5` 秒，第一版范围 `0-5` 秒，精度 `0.1` 秒；最后一段同样添加所设停顿。
- 输出格式、采样率等全局设置从中栏移至右栏，保留现有单人模式支持的选项。多人分句先使用适合合并的规格，最终按用户输出设置编码。
- 未绑定音色、无兼容模型、空段落和超限内容，提交前提供简洁中文校验信息。

多人第一版限制为最多 `20` 个角色、`100` 段，合计正文不超过 `8000` 字符；每段还受实际模型的单次文本限制约束。前后端使用相同限制。

## 4. 角色识别与语速规则

角色识别不调用额外大模型，不增加识别费用。按行首角色前缀解析，支持 `Student A:`、`Student B：`、`学生甲：`、常见括号角色标签以及换行续写。角色按首次出现顺序建立稳定标识，同名角色复用映射。

识别仅处理角色形式明确的行首标签，不剥离时间、URL、正文内部冒号等内容。每个带角色标签的行开始一段；后续无标签的非空行追加到该段，保留换行。首个标签之前的正文形成未分配段落，空行不产生空段落，不猜测丢弃内容；用户可以手动归属角色。识别前后的正文顺序必须一致。

语速使用用户理解的倍速表示；转换到供应商参数由服务端能力映射负责。复用既有 TTS 参数规范，补充按供应商及模型判断的能力。当前 ElevenLabs 适配范围 `0.7-1.2`，其他模型遵循已有规则及实际能力；不对所有模型一律展示 `0.5-2`。音色变更导致旧语速不兼容时要求用户调整并重新确认费用。

## 5. 持久化与任务边界

新增持久化的整篇配音项目、按序分段及生成批次。项目保存所有者、当前身份、场景与扣费空间快照、角色映射、正文版本、输出设置和最新完整音频。段落保存稳定 ID、顺序、角色、正文、语速、停顿、音频输入指纹和当前有效音频引用。

生成批次保存不可变输入快照、逐句模型与报价、确认标识、冻结与结算状态、处理进度和失败信息。分句 TTS 继续使用现有 AudioTask 与 AudioAsset，关联生成批次和段落，不另造供应商执行层。

音频输入指纹包含正文、实际音色、模型与合成参数；停顿与最终格式另计为合并指纹。只有输入指纹一致且音频可用，才允许复用已付费分句。变更停顿不使分句音频失效。

项目状态区分未生成、待处理、合成中、部分失败、合并中、完成和失败。旧的完整音频在新版本完全保存成功前保持可用，并明确标识它对应的版本，不能冒充当前修改后的结果。

左栏合并展示本体验区单人记录与多人项目记录。多人仅展示整篇项目；分句子任务在服务端通过显式关联排除，不仅依赖前端或客户端传入的 `source`。

## 6. 费用确认与执行

服务端按当前角色绑定解析实际模型，以已有字符计数、单价、计价单位及点数换算规则逐句计算。确认弹窗展示角色、模型、计费字符数、逐句点数与总点数，必要时展示对应人民币参考值。已可复用的分句显示复用、不重复计费。

费用确认绑定正文版本、音色、模型、合成参数、输出设置和扣费空间，时效为 `10` 分钟。用户改动相关内容、报价过期、可用模型或价格变化后必须重新获取报价，不能沿用旧确认继续扣费。客户端提交总费用不作为计费依据。

确认提交先原子预留整个待合成批次的总点数，余额不足则不发起任何供应商请求。复用现有个人点数和企业空间计费辅助接口，不重写钱包余额运算。生成子任务使用父批次外部计费上下文，禁止子任务再次冻结或扣费。

同一个确认标识只允许消费一次，重复提交返回同一已创建批次或明确冲突。相同项目不并发执行互相覆盖的版本；领取任务和结算均使用事务与幂等标识。

各句按照确认的模型快照执行，成功且获得可恢复的音频后记录结果。结算只收取成功分句的确认费用，不超过确认总额；失败与未执行部分释放。重新生成或失败重试只为需要执行的句子创建新的报价和批次。

成功分句付费状态与合并状态分开。合并或最终 R2 上传失败时保留成功分句，不重复发起供应商 TTS；只做合并、保存重试。分句的 R2 保存失败时，在有界的临时结果缓存中保留已取得的供应商音频以便存储重试，缓存与重试不额外扣模型费用。缓存不可恢复时不得将未持久化分句标记为成功。

## 7. 后台执行与故障恢复

提交返回持久化批次 ID，不依靠长时间浏览器请求完成全部合成。工作台轮询或使用现有刷新机制展示段落状态和整篇进度，刷新页面不会重新合成。

采用数据库持久化待执行状态与任务租约，后台执行器按可用容量领取工作，限制并发和每次处理量。续租、检查点与结算写入数据库；进程重启能够保留已完成段落并恢复尚未开始的工作。不会仅使用未跟踪的内存 Promise 作为任务队列。

供应商请求结果不确定时，不盲目重放产生可能重复扣费的请求；利用已有可查询的请求标识恢复，无法恢复则将该句转为可显式重试的失败状态。尚未成功落盘的费用不重复结算，旧执行器失去租约后不能覆盖新的结果。

## 8. 音频合并与 R2

分句和最终文件均使用现有 S3 兼容配置保存到 Cloudflare R2，使用项目、批次和分句版本构造对象键，不覆盖旧版本。兼容 Base64 音频与供应商返回的临时 URL，不将临时供应商 URL 当作最终可下载资源。

合并使用 FFmpeg：将各来源音频解码到统一采样率、声道和 PCM 规格，逐句添加尾部静音，按原顺序连接，最后一次编码到所选格式。不能直接拼接 MP3 字节，也不能只在播放器里模拟停顿。通过 ffprobe 验证成品格式、可解码性与时长，最终时长包含全部段尾停顿。

下载来源只能是服务端已验证的音频资源或允许的供应商域名，防止任意地址访问。限制单文件大小、总临时磁盘用量、处理时长与重定向；FFmpeg 使用参数数组而非 shell 拼接。临时文件在成功、失败和超时后清理。

对象上传并验证后才发布完成状态；保存失败不显示假成功，不返回 Base64 作为多人完整文件的长期结果。播放与下载直接使用已保存的有效结果，不能只提示刷新。前端同时提供整篇播放、下载与逐句试听。

## 9. 权限与回归

所有项目、分句、报价、重试和合并接口均需登录，遵循现有选中身份与 `article-to-speech` 授权检查。服务端校验用户、学习者和组织归属；客户端不能通过指定项目 ID、分句 ID、音频资产或扣费空间读取与修改他人数据。

学习者仅使用当前策略允许的音色与个人扣费，不能借多人接口绕过角色限制。项目执行时保留身份归因，不因页面切换身份而改变已确认批次的扣费主体。错误提示保持中文，不暴露密钥、内部异常或供应商原始堆栈。

保留现有单人自动匹配、已选择音色、播放下载和历史过滤行为，不改动其他应用的 TTS 历史或扣费。

## 10. 验收

实施采用严格模式：关键流程先写失败测试，再实现，完成后独立审查并最终验真。

- 角色识别：中英标签、全半角冒号、括号标签、续行、空行、时间与 URL、无标签文本、角色复用和正文顺序。
- 模型与语速：跨供应商音色、自动匹配、不可用模型、ElevenLabs 范围及变更音色后的参数失效。
- 报价与扣费：混合模型逐句汇总、旧报价拒绝、余额不足不调用模型、重复提交、部分失败释放、企业与个人空间、子任务不重复扣费。
- 单句替换：只执行改动句，复用其余音频；改停顿只合并；合并失败保留分句和旧完整版本。
- 状态与权限：刷新恢复、租约过期、进程重启、越权项目和资产、学习者音色策略、子任务历史排除。
- 音频与存储：真实 FFmpeg 小样本合并、不同音频规格、尾部停顿时长、R2 保存验证、上传失败与重试、临时文件清理、成品播放下载。
- 页面：桌面及移动端截图，统一编辑外框、右栏全部设置、头像与按钮布局、费用确认、生成进度与单句操作，无文本重叠和横向溢出。

主要验收命令：

```bash
pnpm --filter @xueleai/database db:generate
pnpm --filter @xueleai/api-core typecheck
pnpm --filter @xueleai/web typecheck
pnpm --filter @xueleai/api-core test
pnpm --filter @xueleai/web test
pnpm --filter @xueleai/api-core build
pnpm --filter @xueleai/web build
```

针对性测试采用各包已有 `node --import tsx --test` 工具链，计划中列出确切新测试文件。数据库使用本项目独立的本地或测试库验证 migration，不操作生产数据库。验收页面为本地 `/experience/voice`，服务端端口遵循仓库 `3320-3329` 固定规则。
