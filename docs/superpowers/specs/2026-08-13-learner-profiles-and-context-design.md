# 多学习者档案、授权与身份上下文设计

**日期：** 2026-08-13

**状态：** 已确认

**范围：** 多学习者档案、学习者白名单授权、登录后身份选择、安全切换、现有创作与学习记录归属，以及后续打卡和学习分析的数据基础

## 1. 目标

一个普通用户账号可以添加多个学习者，并为每个学习者分别维护昵称、学段年级、头像、场景应用授权和课程授权。用户每次登录后先选择“我的账号”或某个学习者，再进入对应界面。

系统必须在服务端识别当前使用身份，并把学习者模式下新产生的创作、学习和复习记录归属到该学习者。在不立即开发打卡或分析看板的前提下，记录后续计算学习天数、完成量、课程进度和学习情况所需的基础事件。

本功能的核心目标是形成以下可见闭环：

1. 用户登录后选择“我的账号”或学习者。
2. “我的账号”添加、编辑、停用学习者并配置白名单授权。
3. 学习者只看到和使用获授权的场景应用及课程。
4. 离开学习者模式时按目标身份执行对应密码验证。
5. 新产生的业务记录和活动事件可靠归属到当前学习者。

## 2. 核心概念与非目标

### 2.1 核心概念

- `User` 是用户本人、登录主账号、数据所有者、付费主体和管理权限主体，界面名称固定为“我的账号”。
- 系统中不建立“创作者”概念，不显示“创作者”文案，也不创建创作者档案或创作者授权表。
- `Learner` 是 `User` 账号下可独立授权和记录过程的学习者档案，不是可独立登录的子账号。
- 一个 `User` 可以拥有多个 `Learner`；一个 `Learner` 只能属于一个 `User`。
- “我的账号”拥有该用户原本具备的全部权限。白名单授权只约束学习者，不约束“我的账号”。

### 2.2 非目标

本期不实现：

- 学习打卡页面、连续打卡规则或补签。
- 学习分析、统计聚合、图表或家长报告。
- 学习者独立登录、独立邮箱、独立手机号或独立钱包。
- 每个学习者单独的切换密码。
- 创作者身份、创作者授权或创作者档案。
- 学习者之间的数据共享。
- 支付课程购买能力或新的课程交易模型。
- 复杂角色权限、组织成员改造、多语言或 AI Agent 编排。

## 3. 已选方案

采用“主账号下的独立学习者模式”：

- 保留现有 `User` 登录、JWT、刷新令牌、钱包和业务所有权关系。
- 新增学习者档案、学习者授权关系和服务端可信的当前身份上下文。
- 现有业务记录继续保留 `userId`，并增加可空的 `learnerId`。
- `userId` 决定所有权、计费和账号边界；`learnerId` 决定本次创作或学习过程归属于哪个学习者。
- 后端从已验证的身份上下文写入 `learnerId`，不信任客户端提交的任意学习者 ID。

不采用子账号方案，因为学习者无需独立登录、账号找回和凭证生命周期。不采用只在前端保存身份的方案，因为它无法防止绕过白名单或伪造记录归属。

## 4. 学习者档案

### 4.1 字段

`Learner` 包含：

- `id`：学习者 ID。
- `userId`：所属主账号。
- `nickname`：昵称，必填，去除首尾空格后长度为 1–30 个字符。
- `grade`：学段年级，必填，使用固定枚举。
- `avatarUrl`：头像地址，可空。
- `status`：`ACTIVE` 或 `INACTIVE`。
- `createdAt`、`updatedAt`、`deactivatedAt`。

同一主账号下允许学习者昵称重复；界面使用头像、昵称和学段年级共同帮助用户识别。未上传头像时，前端使用昵称首字符生成默认头像，不持久化生成图。

### 4.2 学段年级

学段年级严格使用以下 14 个选项：

```text
学龄前
一年级
二年级
三年级
四年级
五年级
六年级
七年级
八年级
九年级
高一
高二
高三
大学和工作
```

“大学和工作”是一个合并选项，用于覆盖非中小学学习者，不拆分成“大学”和“工作”。数据库保存稳定枚举值，API 返回对应的固定简体中文标签。

### 4.3 增改、停用与历史

- “我的账号”可以添加、编辑和停用学习者。
- 删除操作在产品界面表达为“停用”，必须二次确认，不物理删除学习者。
- 已停用学习者不能再被选择，已有身份上下文立即失效，历史业务记录、授权记录和活动事件全部保留。
- “我的账号”默认只列出有效学习者，可切换查看已停用学习者及其历史。
- 已停用学习者可以恢复；恢复后原授权继续有效，但仍要重新通过身份选择进入。

### 4.4 头像

学习者头像复用现有用户头像上传的 MIME、大小和存储安全限制。媒体资产仍归主账号所有，学习者档案只保存头像 URL 或媒体解析后的安全地址。上传接口必须验证目标学习者属于当前用户；学习者模式不能修改头像。

## 5. 身份选择与身份上下文

### 5.1 登录后的入口

- 所有用户登录方式成功后都进入 `/select-profile`，而不是直接进入 `/dashboard` 或恢复上次身份。
- 登录流程允许保留原本安全的 `next`，但只有完成身份选择后才能继续该目标；无目标时选择“我的账号”进入 `/dashboard`，选择学习者进入学习者首页。
- 身份选择页展示“我的账号”和当前账号下全部有效学习者。
- 从身份选择页选择“我的账号”或任一学习者都不需要输入密码。
- 用户没有学习者时，页面仍显示“我的账号”，并提供进入账号后添加学习者的入口。
- 重新登录会重置为“尚未选择身份”；刷新页面和打开同站点新标签页会保持当前已选身份。

### 5.2 服务端可信上下文

身份状态不得只保存在 Zustand、`localStorage`、查询参数或客户端提交的 `learnerId` 中。后端以当前用户刷新会话为持久化边界保存身份状态，并签发一个与该刷新会话绑定的 `HttpOnly` 身份上下文 Cookie。两者共同表示：

```text
UNSELECTED
ACCOUNT
LEARNER(learnerId)
```

刷新会话保存模式和可选 `learnerId`；Cookie 至少包含当前 `userId`、刷新会话 ID、模式、可选 `learnerId`、签发时间和过期时间，并满足：

- 使用服务端密钥签名，生产环境启用 `Secure`，使用 `SameSite=Lax`，路径为 `/`。
- 身份上下文必须与当前已验证的用户会话 `userId` 一致；单独持有身份 Cookie 不能通过鉴权。
- 每次解析时，Cookie 中的刷新会话 ID、模式和学习者必须与数据库中当前未撤销的刷新会话一致；仅删除、替换或回滚 Cookie 不能把已选学习者重置为免密码选择状态。
- 生命周期不得超过当前用户刷新会话；登录时覆盖为 `UNSELECTED`，退出时清除。
- 身份选择和切换在数据库中原子更新当前刷新会话，再签发匹配的新 Cookie。只有退出并重新登录产生的新刷新会话会恢复为 `UNSELECTED`。
- 每次读取 `LEARNER` 上下文时都验证学习者仍属于该用户且状态为 `ACTIVE`。
- 学习者不存在、已停用或不属于当前用户时，撤销当前刷新会话并要求重新登录；不得把该会话降级为可免密码选择的 `UNSELECTED`。

前端可以缓存展示所需的当前身份，但服务端身份上下文是权限判断和数据归属的唯一事实来源。

### 5.3 路由行为

- `UNSELECTED` 访问需要登录的普通用户页面或业务 API 时，页面重定向到 `/select-profile`，API 返回固定中文错误与可识别错误码。
- `ACCOUNT` 保持用户现有完整权限。
- `LEARNER` 进入学习者首页，只展示已授权场景应用、已授权课程和属于当前学习者的历史。
- 学习者模式不能访问个人资料、账单、组织账号、学习者管理、课程编排等主账号页面；直接输入地址同样被服务端页面守卫或 API 权限守卫拦截。
- 公开页面仍按现有规则访问；一旦执行需要登录或产生记录的操作，必须使用当前身份上下文。

## 6. 切换密码与安全切换

### 6.1 共享切换密码

- 一个 `User` 只有一个共享切换密码，供所有学习者之间切换时使用。
- 切换密码必须是恰好 6 位的纯数字。
- 只保存强密码哈希，不保存明文，不在任何 API 中返回原值。
- 不设置连续输错锁定。
- 错误切换密码只返回固定简体中文错误，不透露其他账号信息。

可以在 `User` 上增加可空 `learnerSwitchPasswordHash`，避免为当前单一密码需求引入独立凭证体系。

### 6.2 设置与修改

- 创建第一个学习者时，用户必须同时设置 6 位切换密码。
- 添加后续学习者时复用账号已有切换密码，不再次要求设置。
- “我的账号”可以修改切换密码；修改前必须验证主账号登录密码。
- 通过手机验证码等方式创建、尚无用户可输入密码的账号，必须先设置主账号登录密码，才能创建第一个学习者。
- 系统不得用短信验证码或切换密码代替返回“我的账号”时的主账号密码验证。

### 6.3 切换矩阵

| 当前状态 | 目标状态 | 验证要求 |
| --- | --- | --- |
| 登录后尚未选择 | 我的账号 | 无 |
| 登录后尚未选择 | 任一有效学习者 | 无 |
| 我的账号 | 任一有效学习者 | 无 |
| 学习者 A | 学习者 B | 验证账号共享的 6 位切换密码 |
| 学习者 A | 我的账号 | 验证主账号登录密码 |
| 任意已选身份 | 退出登录 | 无 |

学习者 A 不能以自己为目标执行无意义切换。密码验证成功和身份上下文更新在同一次服务端请求中完成；验证失败时保持原身份。

## 7. 学习者授权

### 7.1 严格白名单

每个学习者分别维护：

- `LearnerScenarioAuthorization`：获授权的场景应用。
- `LearnerCourseAuthorization`：获授权的课程。

两类授权均采用严格白名单：学习者只能看到和使用当前有效授权，未授权内容不可见且不可通过直接 API 调用使用。授权列表允许为空；为空时学习者首页显示简洁空状态，引导由“我的账号”配置授权。

### 7.2 场景应用授权

- 授权目标使用现有 `AiScenario` 稳定 ID，不复制场景名称或配置。
- “我的账号”只能授权当前启用、面向用户可用的场景应用。
- 场景应用被平台停用后，即使授权关系仍存在，学习者也不能看到或使用；重新启用后原授权恢复有效。
- 平台以后新增的场景应用不会自动授权给已有学习者。

所有受管场景的列表、详情、执行和历史查询 API 都必须执行同一服务端授权解析，不能只在工具列表页过滤。

音频任务接口同样属于场景执行边界。通用 TTS 请求在学习者模式下必须携带具体 `AiScenario` ID，并验证该场景已授权且具备 TTS 能力；语音复刻和声音设计接口分别映射到固定场景 `my-voice-clone` 与 `brand-voice-design`。`/experience/voice` 归入 `article-to-speech` 场景授权。客户端提供的场景只能作为待校验目标，不能代替服务端授权判断。

### 7.3 课程授权

可授权课程来自主账号当前有权访问且存在可学习版本的课程：

- 主账号自己创建并已有审核通过版本的课程。
- 主账号通过现有 `CourseEnrollment` 加入的已发布课程。
- 后续课程购买能力接入统一课程访问解析器后，主账号已购买的课程。

本期不实现课程购买，也不把尚无审核通过版本的自建草稿课程授权给学习者。授权课程读取最后一个有效审核通过版本。

当主账号失去课程访问权、课程不再具有可学习版本或课程被平台禁用时，学习者授权立即停止生效，但不删除授权行或既有学习记录；主账号重新获得访问权后原授权恢复有效。新创建、新加入或未来新购买的课程不会自动授权。

### 7.4 授权管理

- 只有“我的账号”可以读取和修改学习者授权。
- 授权更新使用服务端事务，提交的是该学习者两类白名单的完整目标集合。
- 服务端验证所有目标属于可授权范围，并以复合唯一键防止重复授权。
- 撤销授权只阻止后续入口和操作，不删除业务历史或活动事件。
- 学习者模式不能修改自己的档案、授权或切换密码。

## 8. 数据所有权与记录归属

### 8.1 双层归属

原有 `userId` 继续存在并保持原语义：

- 数据所有者和安全边界。
- 钱包、点数、订单和计费主体。
- 主账号的汇总查询条件。

在需要区分创作或学习过程的主要业务记录上增加可空 `learnerId`：

- `null`：由“我的账号”产生，或属于迁移前无法判断身份的历史数据。
- 非空：由对应学习者模式产生。

数据库关系和服务层都必须保证 `learnerId` 所属 `userId` 与业务记录的 `userId` 一致。客户端业务 DTO 不提供可任意指定的 `learnerId`；服务端只从身份上下文写入。

### 8.2 本期直接归属的记录

本期为以下主要记录增加学习者归属，并在所有新建、列表和详情路径中应用：

- `AiTask`。
- `AudioTask`。
- `VideoGuideLesson`。
- `EnglishGuidedStudyMaterial`。
- `LearningFlashcardDeck`。
- `LearningFlashcardReview`。
- `CopybookRecord`。

依附于这些主记录的调用日志、资产、卡片、课程课件引用和计费流水通过主记录或 `userId` 追溯，不重复增加 `learnerId`，避免同一业务链出现多个互相矛盾的归属字段。后续新增独立学习功能时，必须在其主记录上遵循同样的 `userId + learnerId?` 规则。

课程编排只能由“我的账号”操作，因此 `Course` 本期不增加 `learnerId`。学习者对课程的使用通过授权和活动事件记录。

### 8.3 查询隔离

- 学习者模式下，业务历史查询固定使用 `userId = 当前用户` 且 `learnerId = 当前学习者`。
- 学习者不能读取 `learnerId = null`、其他学习者记录或仅凭资源 ID 越权访问详情。
- “我的账号”可以读取该 `userId` 下全部记录，并按“我的账号”、具体学习者和全部进行筛选。
- 现有历史数据迁移后保持 `learnerId = null`，不根据标题、时间或其他弱信号猜测学习者。
- 学习者被停用或授权被撤销后，主账号仍可查看既有历史；学习者恢复后只在当前授权允许的入口中继续使用。

### 8.4 计费

学习者不是钱包主体。学习者模式产生的 AI、音频、字帖等消耗仍使用主账号钱包、预留和流水逻辑。账单和钱包只在“我的账号”可见。任务上的 `learnerId` 用于归属和后续分析，不改变现有计费幂等键及财务归属。

## 9. 活动事件基础

新增追加式 `LearnerActivityEvent`，用于后续打卡和学习分析，包含：

- `id`。
- `userId`。
- `learnerId`，活动事件中必填；“我的账号”的普通操作不写入学习者活动事件。
- `eventType`：稳定的行为类型，例如 `CREATE_STARTED`、`CREATE_COMPLETED`、`LEARNING_STARTED`、`LEARNING_COMPLETED`、`REVIEW_COMPLETED`。
- `scenarioId`：可空，关联场景应用。
- `courseId`：可空，关联课程。
- `resourceType`、`resourceId`：可空的业务资源定位。
- `occurredAt`：行为实际发生时间。
- `metrics`：可空 JSON，只保存分析需要的结构化数值或状态。
- `createdAt`。

事件写入规则：

- 事件必须由服务端在真实业务成功节点写入，不能由客户端直接声明“完成”。
- 创建或学习成功与活动事件尽量在同一数据库事务中写入；外部异步任务则在最终状态持久化时幂等写入。
- 对可重试完成事件提供稳定幂等键或等价唯一约束，避免重复统计。
- `metrics` 可以保存时长、完成数量、得分、复习评级等低敏数据，不复制 AI 输入、完整课程内容、字幕或用户上传正文。
- 本期只记录事件，不建立日聚合表，也不计算连续打卡、学习报告或推荐结论。

首期事件覆盖本次纳入归属的主要业务操作；事件类型使用集中定义的常量，后续分析代码不得依赖页面文案。

## 10. 页面与交互

### 10.1 身份选择页

`/select-profile` 显示：

- 页面标题“选择使用身份”。
- “我的账号”卡片，使用用户当前头像和昵称。
- 多个有效学习者卡片，显示头像、昵称和学段年级。
- 没有学习者时的“添加学习者”入口，该入口先进入“我的账号”再打开学习者管理。

页面文案保持简洁，不展示大段身份概念说明。

### 10.2 学习者管理

在用户中心增加“学习者管理”页面，提供：

- 有效和已停用学习者列表。
- 添加、编辑、停用、恢复学习者。
- 头像上传。
- 场景应用白名单和课程白名单编辑。
- 设置或修改 6 位切换密码。

创建第一个学习者使用一个完整表单，同时提交学习者资料、切换密码和可为空的两类授权；没有可输入主账号密码时先引导设置主账号密码。

### 10.3 学习者首页

学习者首页显示：

- 当前学习者头像、昵称和学段年级。
- 获授权的场景应用。
- 获授权的课程。
- 当前学习者最近的创作与学习记录。
- 对授权为空的应用区或课程区分别显示简洁空状态。

学习者界面不显示账单、组织、个人资料、学习者管理和课程编排入口。

### 10.4 身份切换

学习者界面的身份菜单提供：

- “切换学习者”：选择目标后输入 6 位切换密码。
- “返回我的账号”：输入主账号登录密码。
- “退出登录”：直接退出。

验证弹窗不预先显示或泄漏账号是否具有某种登录方式；不满足返回条件时提供进入账号安全设置的明确中文提示。

## 11. API 边界

### 11.1 身份上下文 API

- 查询身份选择页所需的“我的账号”、有效学习者和当前上下文。
- 从 `UNSELECTED` 选择“我的账号”或学习者。
- 从 `ACCOUNT` 进入学习者。
- 验证切换密码后从一个学习者进入另一个学习者。
- 验证主账号登录密码后从学习者返回“我的账号”。

### 11.2 学习者管理 API

- 列出当前账号学习者，包括可选的停用状态筛选。
- 创建、更新、停用和恢复学习者。
- 上传学习者头像。
- 查询可授权场景应用和课程。
- 读取并整体更新单个学习者的两类授权。
- 设置或修改共享切换密码；创建后不提供“读取密码”接口。

### 11.3 业务 API 集成

建立统一的身份上下文解析器和学习者访问守卫，供现有 AI、音频、视频带学、英语带学、闪卡、字帖、课程和历史 API 使用。各模块不得自行从请求体解析 `learnerId`，也不得只依赖前端隐藏入口。

所有 NestJS API 继续使用统一响应结构：

```ts
{
  code: number
  message: string
  data: unknown
}
```

预期失败使用固定简体中文提示，例如“请先选择使用身份”“该学习者已停用”“当前学习者未获得此应用授权”“当前学习者未获得此课程授权”“切换密码错误”“主账号密码错误”。底层 Prisma、JWT 或哈希错误不得暴露给前端。

## 12. 数据迁移

需要一次向前兼容的 Prisma migration：

1. 新增学习者状态和学段年级枚举。
2. 新增 `learners`。
3. 在 `users` 增加可空的 `learner_switch_password_hash` 和是否已设置可输入登录密码的标记。
4. 在用户刷新会话增加 `profile_mode` 和可空 `profile_learner_id`，用于防止通过删除身份 Cookie 绕过切换验证。
5. 新增学习者场景应用授权表和课程授权表及复合唯一索引。
6. 在本期覆盖的主要业务记录增加可空 `learner_id` 和查询索引。
7. 新增 `learner_activity_events` 及按学习者、时间、课程、场景和资源查询所需的索引。

所有新增业务记录的 `learnerId` 初始为空，因此历史数据自然归入“我的账号”。迁移不回填、不删除、不重置生产数据，不修改现有用户密码、钱包、课程审核状态或授权数据。

`Learner` 被停用时使用软状态；外键默认采用限制删除或保留历史的策略，不级联删除学习记录和活动事件。

## 13. 安全与一致性

- 所有学习者管理与授权写操作要求已登录且当前为 `ACCOUNT`。
- 任何学习者 ID 都先验证归属当前 `User`。
- 身份切换只通过专用 API 更新签名身份上下文。
- 已选身份同时绑定当前未撤销的刷新会话；缺失、过期或与会话状态不一致的身份 Cookie 不得降级为可免密重新选择。
- 切换密码和登录密码使用现有安全密码哈希能力与常量时间校验。
- 切换密码不锁定是已确认产品规则；接口仍沿用通用速率限制和安全日志，避免形成无限高频尝试端点。
- 修改切换密码和返回“我的账号”都必须验证可输入的主账号密码。
- 学习者模式的所有资源读取同时校验 `userId`、当前 `learnerId` 和必要授权。
- 授权变更、学习者状态变更和身份切换不得依赖前端缓存即时生效。
- 关键创建或完成记录与活动事件使用事务或幂等写入，避免业务成功但事件丢失或重试产生重复事件。
- 安全日志可以记录用户 ID、学习者 ID、动作和结果，但不得记录任何明文密码、AI 完整输入或上传正文。

## 14. 测试与验收

### 14.1 自动化测试

数据库与后端测试覆盖：

- 14 个固定学段年级值，“大学和工作”为单一值。
- 一个用户创建多个学习者，跨用户修改、停用、授权均被拒绝。
- 首个学习者同时设置 6 位切换密码；非 6 位或非纯数字被拒绝。
- 无可输入主账号密码的用户不能创建首个学习者，设置密码后可以创建。
- 授权列表允许为空，场景和课程复合唯一约束有效。
- 只能授权主账号当前有权访问且可学习的课程。
- `UNSELECTED`、`ACCOUNT`、`LEARNER` 三种上下文的服务端解析。
- 登录后重置选择、刷新保持选择、退出清除选择。
- 从“我的账号”进入学习者无需验证。
- 学习者之间切换只接受共享的 6 位切换密码。
- 学习者返回“我的账号”只接受主账号登录密码。
- 学习者停用后已有上下文立即失效。
- 客户端无法通过请求体、查询参数或伪造 ID 指定其他 `learnerId`。
- 未授权场景和课程在列表、详情及执行 API 中均不可访问。
- 本期各主要业务记录在账号模式写入 `learnerId = null`，在学习者模式写入当前学习者 ID。
- 学习者历史相互隔离，“我的账号”可以汇总并筛选。
- 旧记录保持 `learnerId = null`。
- 撤销授权或停用学习者不会删除历史。
- 业务完成事件幂等写入，且不包含完整学习内容。

前端测试覆盖：

- 登录和注册完成后进入身份选择页，并安全保留原 `next`。
- 身份选择卡片、学习者空列表和停用学习者隐藏。
- 学习者管理表单、14 个学段选项、头像和两类可空授权。
- 学习者首页仅展示授权内容和当前学习者历史。
- 学习者模式隐藏并拦截主账号导航。
- 两种离开学习者路径显示对应密码弹窗和中文错误。

### 14.2 浏览器验收

1. 登录后看到“选择使用身份”，可进入“我的账号”。
2. 添加第一个学习者时设置 6 位切换密码，授权可以全部留空。
3. 添加第二个学习者，并为两个学习者配置不同的应用和课程。
4. 从“我的账号”无密码进入任一学习者。
5. 学习者只看到自己的授权内容和历史，直接输入未授权地址也不能访问。
6. 从学习者 A 切到学习者 B 时必须输入共享切换密码。
7. 从任一学习者返回“我的账号”时必须输入主账号登录密码。
8. 刷新和新标签页保持身份，退出再登录后重新选择。
9. 分别用“我的账号”和两个学习者产生记录，确认主账号可汇总筛选、学习者只能看到自己的记录。
10. 停用学习者或撤销授权后，访问立即失效且历史仍由“我的账号”可见。

## 15. 允许与禁止修改范围

实施预计允许修改：

- `packages/database`：Prisma schema、migration 和相关数据库契约测试。
- `apps/api-core`：身份上下文、学习者管理、授权、业务归属和活动事件集成。
- `apps/web`：身份选择、学习者管理、学习者首页、切换交互、路由守卫和业务页面身份适配。
- 与本功能直接相关的测试和实施文档。

实施禁止顺手修改：

- 支付渠道、钱包账务规则和订单模型。
- 管理员角色、CMS、多语言和组织权限架构。
- AI Gateway 或模型路由。
- 打卡、统计聚合和学习分析页面。
- 当前工作区中与本功能无关的在途改动。
